## 1. 概述

系统对两类内容做原创性检测，采用两套**独立**的相似度内核：

| 模式 | 处理对象 | 内核 | 核心思路 |
| --- | --- | --- | --- |
| 文本查重（TEXT） | 论文、报告、读后感、在线填写文本 | `text.py` | 分词 → N-gram 分片 → Jaccard + 余弦 + SimHash 汉明三路指纹融合 |
| 代码查重（CODE） | 编程作业源码（.java/.py/.c/.cpp/.js/.ts/.go/.cs/.rs 等） | `code.py` | 注释剥离 → 标识符归一化 → Token 序列 → 分片 + 序列 + 词频三路结构指纹融合 |

两套内核都输出 `[0, 1]` 的相似度，再由 `report.py` 按**权重聚合**为 `[0, 100]` 的总相似度（%），并根据阈值映射为 `PASS / WARNING / SEVERE` 三级结论。

所有计算均基于**候选提交**与**比对源（sources）**之间的一对多比较。第一轮仅启用**本班库（CLASS）**，即同课程同作业的其他已提交作业；互联网库、文献库、历届库为后续轮次能力。

---

## 2. 总体处理流程

```
提交文件 + 在线文本
        │
        ▼
[1] 内容抽取与解码      content.py   PDF/DOCX/文本/代码分类
        │
        ▼
[2] 模式选择            report.py::_mostly_code   文本模式 / 代码模式
        │
        ▼
[3] 预处理与归一化       text.py::clean_text / code.py::normalize_source
        │
        ▼
[4] 特征提取            分词、N-gram、SimHash、Token、函数抽取
        │
        ▼
[5] 相似度计算          句子级 / 文件级 / 函数级 指纹融合
        │
        ▼
[6] 聚合与分级          按权重合成总相似度 → PASS / WARNING / SEVERE
        │
        ▼
[7] 报告组装            report.py  →  JSON（算法版本、参数、分段、来源）
```

任务级编排在 `worker.py` 中完成：数据库任务表以 `FOR UPDATE SKIP LOCKED` 领取任务，心跳阶段推进为 `COMPARING → REPORTING`，最终生成 JSON 报告并记录候选输入的 SHA-256 摘要（`input_digest`）用于溯源与防篡改。

## 3. 内容抽取与文件分类（`content.py`）

**解码策略**（`decode_source`）：按 `utf-8-sig → utf-8 → gb18030 → latin-1` 依次尝试解码字节，全部失败则用 `utf-8` 加替换符兜底，兼容中文常见编码。

**文本抽取**（`extract_text`）：

| 后缀 | 处理 |
| --- | --- |
| `.pdf` | `pypdf` 逐页提取文本 |
| `.docx` | `python-docx` 提取段落与表格单元格 |
| `.txt/.md/.rst/.csv/.json/.xml/.yaml/.yml` 及代码后缀、无后缀 | 直接按编码解码（前 4KB 含 `\x00` 判为二进制，返回空） |
| 其他 | 不纳入比对 |

**代码/文本分流**（`split_candidate_files`）：后缀命中 `LANGUAGES` 的作为**代码文件**单独保存（`code_files`），其余可读文本并入**正文文本**（`text_parts`，以 `# 路径` 标注来源文件）。

```python
LANGUAGES = {".java":"JAVA", ".py":"PYTHON", ".c":"C", ".h":"C",
             ".cpp":"CPP", ".cc":"CPP", ".hpp":"CPP", ".js":"JAVASCRIPT",
             ".ts":"TYPESCRIPT", ".go":"GO", ".cs":"CSHARP", ".rs":"RUST"}
```

## 4. 模式选择（`report.py`）

`build_report` 根据候选文件是否"主要为代码"决定走哪条路径：

```python
def _mostly_code(files):
    code_files = [p for p in files if detect_language(p) != "TEXT"]
    return bool(code_files) and len(code_files) >= max(1, len(files) // 2)
```

即：**至少有一个代码文件，且代码文件数不少于文件总数的一半（向下取整）**时进入代码模式，否则进入文本模式。

- 文本模式：比对 `candidate_text` 与各来源的 `source.text`。
- 代码模式：比对 `candidate_files` 与各来源的 `source.files`（逐文件）。

> 混合提交（文档内含代码段）第一轮不拆段，按"主要为代码"整体归入某一模式；混合模式拆分属后续轮次。

## 5. 文本查重算法（`text.py` + `report.py::_text_report`）

### 5.1 清洗与归一化（`clean_text`）

```
1. Unicode NFKC 规范化（全角→半角、兼容字符合并）
2. 换行统一：\r\n、\r → \n
3. 参考文献标注剔除（可选，默认开启）
   - [1,2] / [1-3] 编号样式
   - 【1】编号样式
   - (Author, 2024a) 英文作者-年份
   - （张三，2024）中文作者-年份
4. 空白折叠：连续空格/制表/换行缩进 → 单个空格；3 个以上连续换行 → 2 个
5. 首尾去空白
```

参考文献剔除是系统"排除引用"能力的基础，避免把规范引用误判为抄袭；`clean_text` 输出的结果在 `report` 中记录为 `excludedItems` 类型 `REFERENCE`。

### 5.2 分词（`tokenize`）

```python
TOKEN_PATTERN = r"[A-Za-z0-9_]+|[\u3400-\u9fff]"
```

- 连续字母/数字/下划线视为 1 个 token（英文单词、数字）；
- **每个汉字单独成 token**（`\u3400-\u9fff`，覆盖 CJK 扩展 A 与基本区），不做中文分词；
- 统一小写。

### 5.3 三种基础相似度

**① N-gram 分片与 Jaccard（局部重合度）**

```python
def ngrams(tokens, size=3):        # 滑动窗口，相邻 size 个 token 组成一个元组
def jaccard(left, right):          # |A∩B| / |A∪B|
```

- 默认 `size=3`（`config.ngram_size`）；
- 文本不足 `size` 个 token 时，整段作为一个分片；
- `jaccard` 用**集合**去重，反映"是否包含相同的短片段"，对顺序不敏感。

**② 余弦相似度（词频分布）**

```python
def cosine_similarity(left: Counter, right: Counter):
    return Σ(t·u) / (‖t‖·‖u‖)      # 基于 token 频率向量的夹角余弦
```

**③ SimHash + 汉明距离（近重复指纹）**

```python
def simhash(tokens, bits=64):
    # 以 2-gram 为特征，BLAKE2b 哈希到 bits 位，按频次加权投票
def hamming_similarity(left, right, bits=64):
    return 1.0 - (left ^ right).bit_count() / bits
```

- 特征为 **2-gram**（`ngrams(tokens, 2)`）；
- 每个特征以 `blake2b(特征, 8字节)` 哈希出 64 位向量，按词频 `±1` 加权累积，每位取符号得到 64 位指纹；
- 两文档指纹的汉明距离越小 → 内容越近似；`hamming_similarity` 把汉明距离归一化为 `[0,1]` 的相似度。

### 5.4 句子级相似度（`sentence_similarity`）

句子（候选句与来源句）的相似度由三路指纹**加权融合**：

```
sim(句A, 句B) =
    0.45 × Jaccard(ngrams(词A,3), ngrams(词B,3))
  + 0.35 × Cosine(Counter(词A), Counter(词B))
  + 0.20 × Hamming(SimHash(词A), SimHash(词B))
```

权重设计：分片重合度主导（45%），词频分布次之（35%），近重复指纹兜底（20%）。结果裁剪到 `[0,1]`。

> 验证：完全相同的句子 `sim ≥ 0.95`；无关句子 `sim < 0.35`（见 `tests/test_text.py`）。

### 5.5 全文级比较（`compare_texts`）

对候选全文与**每个来源**分别计算综合相似度，返回 `max`（最相似来源）与 `average`（全部来源均值）：

```
score(候选, 来源) =
    0.45 × Jaccard(候选分片, 来源分片)
  + 0.35 × Cosine(候选词频, 来源词频)
  + 0.20 × Hamming(候选SimHash, 来源SimHash)
```

`max` 反映"候选整体最像哪份作业"，`average` 反映"候选与全班的平均重叠水平"。

### 5.6 报告级聚合（`report.py::_text_report`）

报告采用**句子级加权**得到最终文本相似度：

1. 用 `SENTENCE_PATTERN`（按 `。！？!?；;\n` 断句，且长度 ≥ 8 字符）切分候选文本；
2. 对每个候选句，遍历所有来源句，用 `sentence_similarity` 求**最佳匹配**（最高分）；
3. 权重按句长 `weight = max(1, len(句))`，累计：

```
sentence_score = Σ(最佳分 × 句长) / Σ(句长)
```

4. 与全文比较取大，并保留 0.85 的全文权重：

```
text_score = max( sentence_score, compare_texts.max × 0.85 ) × 100
```

5. 裁剪到 `[0, 100]` 得总相似度（%）。

**分段证据**：当某句最佳分 `≥ max(0.15, 文本警告阈值/100 × 0.65)` 时写入 `segments`，记录所属章节（`_section_name` 通过"章/节/部分"标题正则识别）、原文、`charStart/charEnd`、最佳来源、`matchedExcerpt`；当最佳分 `≥ 0.35` 时给出整句 `highlightRanges` 供前端高亮。

**来源视图**：每个来源记录其最高句子分与匹配字符数（`matchedChars`），仅保留分 `> 0.001` 的来源并按相似度降序输出；同班来源脱敏显示为"同班同学提交（匿名）"。

## 6. 代码查重算法（`code.py` + `report.py::_code_report`）

### 6.1 语言识别（`detect_language`）

按扩展名查表（见 §3），未命中返回 `TEXT`。

### 6.2 注释剥离（`strip_comments`）

**保留字符串字面量、保留换行结构**的状态机：

- 识别 `'` 与 `"` 引号（含转义 `\x`），引号内不当作注释；
- `//` 行注释 → 删到行尾；
- `/* ... */` 块注释 → 删除但**保留内部换行**，避免把多行代码并成一行；
- Python（`language == "PYTHON"`）额外识别 `#` 行注释。

### 6.3 归一化（`normalize_source`）—— 抗重命名/抗风格差异

顺序执行：

```
1. strip_comments       去注释
2. 字符串字面量 → 占位符 " <STR> "      （"..."、'...'）
3. 数字字面量 → 占位符 " <NUM> "        （\b\d+(\.\d+)?\b）
4. 标识符重命名：
   - 关键字（if/for/while/return/class/... 等，大小写不敏感）→ 保留并转小写
   - 用户标识符 → 按首次出现顺序替换为 ID1, ID2, ...
```

效果：**仅变量名/注释/格式/字符串/数字不同的等价代码归一化为同一 Token 流**，从而把"改头换面"的复制识别为高度相似（验证：`tests/test_code.py::test_identifier_renaming_preserves_structure`，重命名后相似度 > 0.75）。

> 设计意图：归一化后比较的是**控制流与逻辑结构**，而非字面拼写。教师可通过配置关闭"统一标识符"以保留命名差异（后续轮次参数项）。

### 6.4 Token 化（`code_tokens`）

```python
TOKEN = r"[A-Za-z_][A-Za-z0-9_]*|\d+(?:\.\d+)?|==|!=|<=|>=|&&|\|\||->|=>|::|[^\s]"
```

除标识符、数字外，将复合运算符（`== != <= >= && || -> => ::`）作为**独立 token**，其余单个非空白字符各成一 token。

### 6.5 结构相似度（`structure_similarity`）—— 三路指纹融合

```python
def structure_similarity(left, right, language=None):
    lt, rt = code_tokens(left, language), code_tokens(right, language)
    shingle  = jaccard(token_shingles(lt, 4), token_shingles(rt, 4))        # 4-gram 分片
    sequence = difflib.SequenceMatcher(a=lt, b=rt, autojunk=False).ratio() # 最长公共子序列近似
    frequency= cosine_similarity(Counter(lt), Counter(rt))                 # 词频
    return 0.50*shingle + 0.30*sequence + 0.20*frequency
```

| 指纹 | 权重 | 说明 |
| --- | --- | --- |
| 4-gram 分片 Jaccard | 0.50 | 连续 4 token 窗口重合度，抗顺序微调 |
| 最长公共子序列比率（`difflib`） | 0.30 | 保留顺序的序列相似度，抗插入/删除 |
| Token 频率余弦 | 0.20 | 整体词频分布 |

`token_shingles(tokens, 4)` 生成大小 4 的滑动窗口集合；不足 4 个 token 时整段作一个分片。

### 6.6 函数级匹配（`extract_functions` + `compare_code`）

为抵抗"整文件混入无关代码"的稀释，额外做**函数级**比对：

- **Python**：正则匹配 `def name(...):`，函数体延伸到下一个 `def` 之前；
- **C 系**：匹配 `返回类型 名称(参数) {`，函数体按花括号深度匹配到平衡 `}`。

```python
def compare_code(candidate_path, candidate_source, sources):
    candidate_functions = extract_functions(candidate_source, language)
    for source in sources:
        function_score = max(
            structure_similarity(cand_body, src_body)   # 所有函数两两配对取最大
        )
        whole_score = structure_similarity(candidate_source, source_text)
        combined = max(whole_score, function_score * 0.95)   # 函数级乘 0.95 折扣
```

函数级得分乘 `0.95` 后再与整文件得分取大——**当存在高度相似的函数/方法时，即使整文件相似度不高（被其他函数稀释），也能被函数级匹配兜住**。

### 6.7 报告级聚合（`report.py::_code_report`）

```
对候选的每个文件：
    best_score = max( structure_similarity(候选文件, 来源文件) )   # 遍历所有来源的所有文件
    weight     = max(1, len(候选文件内容))

structure_score = Σ(best_score × weight) / Σ(weight) × 100      # 按文件长度加权
```

每个文件生成一个 `segments` 条目（`matchType=CODE`，记录语言、`matchedFile`、前 2000 字符原文），来源视图按匹配文件数标注"代码结构匹配 · N 个文件"。

## 7. 阈值与分级（`config.py` + `report.py::_level`）

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `text_warning_threshold` | 20.0 | 文本模式警告阈值（%） |
| `text_severe_threshold` | 50.0 | 文本模式严重阈值（%） |
| `structure_warning_threshold` | 30.0 | 代码模式警告阈值（%） |
| `structure_severe_threshold` | 60.0 | 代码模式严重阈值（%） |
| `ngram_size` | 3 | 文本 N-gram 窗口 |
| `simhash_bits` | 64 | SimHash 指纹位数 |
| `max_sources` | 300 | 单次查重最多比对来源数 |
| `libraries` | `["CLASS"]` | 比对库（第一轮仅本班库） |

分级规则：

```python
if score >= severe:   return "SEVERE"
if score >= warning:  return "WARNING"
return "PASS"
```

- 文本模式用 `text_*` 阈值，代码模式用 `structure_*` 阈值；
- 阈值可由作业查重配置快照（`task.config`）覆盖，报告会回写实际生效阈值与算法参数，便于复现（`_envelope` 中的 `thresholds` 与 `params`）。

## 8. 复杂度与规模控制

| 环节 | 复杂度 | 控制手段 |
| --- | --- | --- |
| 文本全文比较 | O(候选token × 来源数) | `max_sources=300` 上限 |
| 文本句子级 | O(候选句 × 全部来源句 × 三路指纹) | 仅句子 ≥ 8 字符参与；分片用集合 |
| 代码整文件 | O(候选文件 × 来源文件) | 每文件仅取最佳来源文件 |
| 代码函数级 | O(候选函数 × 来源函数) | 两两配对取最大 |
| SimHash | O(特征数 × 64) | 固定 64 位，常数因子小 |

> 性能目标（对应功能测试 NFR）：文本 10 万字 ≤ 60s、代码 5000 行 ≤ 90s（P95）。

## 9. 已知局限与后续规划

1. **模式不混查**：混合提交按"主要为代码"整体归入单一模式，未做文档内代码段与文本段拆分（混合模式为后续 FR-K-07 能力）。
2. **中文无分词**：汉字按单字成 token，未用 jieba 等分词器，长中文句的语义区分度依赖 N-gram 与 SimHash。
3. **无 AST**：第一轮用"注释剥离 + 标识符归一化 + Token 序列"近似结构指纹，未引入 tree-sitter AST；函数抽取基于正则。
4. **无候选检索索引**：第一轮不做倒排/LSH 初筛，全量两两比较，靠 `max_sources` 与阈值限流。
5. **比对库单一**：仅本班库；互联网库、文献库、历届库、白名单排除、压缩包六桶分类、三层递进（文本指纹初筛 → AST 结构 → 精确代码块）为后续轮次。
6. **预查重**：第一轮未实现学生自查预查重与配额。

## 11. 验证用例
