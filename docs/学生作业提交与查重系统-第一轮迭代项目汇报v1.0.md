## 四、查重算法说明

### 4.1 总体设计

系统按作业模式分为**文本查重**与**代码查重**两条流水线，共用"预处理 → 特征化 → 相似度合成 → 阈值判定 → 报告落库"的骨架：

```
提交附件 ─▶ 按扩展名分类 ─▶ 文本/代码识别
   │
   ├─ TEXT  ─▶ 编码探测 ─▶ 清洗(NFKC+去引文+压缩空白) ─▶ 分词 ─▶ 三级粒度比对
   └─ CODE  ─▶ 注释剥离 ─▶ 归一化(字符串/数字/标识符) ─▶ 词法单元 ─▶ 结构比对
                                    │
                                    ▼
              与比对库逐个来源比对 ─▶ 白名单库排除(≥0.90 不计分)
                                    │
                                    ▼
              总分校正 ─▶ 等级判定(PASS/WARNING/SEVERE) ─▶ 报告(S3+DB, 不可变)
```

**比对范围**：同一作业的其他学生提交（班级库，默认 `CLASS`）+ 教师选定的其他库（含白名单库），候选上限 `max_sources = 300`。

### 4.2 文本查重

#### 4.2.1 文本获取与清洗

| 步骤 | 实现 |
| --- | --- |
| 编码探测 | PDF 用 pypdf 抽取；DOCX 用 python-docx；纯文本按 `utf-8-sig → utf-8 → gb18030 → latin-1` 顺序回退解码（覆盖 Windows GBK 环境） |
| 规范化 | Unicode **NFKC** 全角转半角，避免字符级假差异 |
| 去引文 | 移除引号包裹内容、引用标记，防止"引用公共素材即被判抄袭" |
| 空白归一 | 连续空白折叠为单空格 |

#### 4.2.2 分词

- **默认（零第三方依赖）**：中文按**单字**切分（CJK 码位逐字成 token），非中日韩按单词切分。这是首轮"无 AST/无中文分词"约束下的可用基线。
- **可选增强（默认关闭，`chinese_seg.enabled`）**：中文滑窗 **2-gram** 分词，缓解单字切分导致的短串误匹配与同字不同义噪声。

#### 4.2.3 相似度合成（核心公式）

候选与来源的相似度由三种互补度量线性加权，最终裁剪到 `[0,1]`：

```
similarity = 0.45 × Shingle(Jaccard)   # n-gram（默认 n=3）集合交并比
           + 0.35 × Cosine(词频向量)     # 词袋频率余弦
           + 0.20 × Hamming(SimHash)     # 64 位 SimHash，simhash = 1 − 汉明距离/64
```

| 度量 | 作用 | 参数 |
| --- | --- | --- |
| n-gram Jaccard | 捕捉"连续片段照搬"，对整句抄袭最敏感 | `ngram_size = 3` |
| 词频余弦 | 对词序变化、同义替换相对鲁棒 | 词袋 `Counter` |
| SimHash + 汉明距离 | 64 位指纹，比对代价 O(1)，抗小幅扰动 | `simhash_bits = 64` |

三者的互补性：Jaccard 对改写不鲁棒、余弦对插入不敏感、SimHash 抗整体扰动——加权后可降低单一度量的误判率。

#### 4.2.4 三级比对粒度

| 粒度 | 计算方式 | 用途 |
| --- | --- | --- |
| **全文** | 全文 vs 全文，取所有来源中的最大值 `full_max` | 反映整体重合度 |
| **段落** | 按段落切分，逐段取最优来源，按段落长度加权平均 → `paragraph_score` | 反映结构级搬运，输出为 `structure_score` |
| **句子** | 按句子切分（`split_sentences`，最短 8 字符），逐句取最优来源，按句长加权平均 → `sentence_score` | 定位到句级，供高亮与判定 |

#### 4.2.5 总分校正

首轮采用 `max(句级, 全级×0.85)`，导致"零散抄袭但句级高"被高估。现改为**可配置加权校正**：

```
text_score = 0.6 × sentence_score + 0.4 × full_max        （text_score_weights，0~100 分，两位小数）
```

权重可由配置快照覆盖，默认 0.6 / 0.4。

#### 4.2.6 高亮区间（真实定位，非占位）

- 对得分 ≥ 0.35 的句子/段落，用 `difflib.SequenceMatcher.get_matching_blocks(autojunk=False)` 在候选与来源文本上定位**真实重叠区间**，生成有序、不重叠的 `highlightRanges`，前端双栏同色渲染。
- 片段收录阈值：`max(0.15, text_warning_threshold/100 × 0.65)`，即默认 20% 阈值下为 15%。

### 4.3 代码查重

#### 4.3.1 归一化（抗"改名/格式化"抄袭）

| 处理 | 说明 |
| --- | --- |
| 注释剥离 | 手写状态机剥离 `//`、`/* */`、`#`、`'''`/`"""`，避免注释抄袭被算入 |
| 字符串字面量 | 整体替换为 `<STR>` |
| 数字字面量 | 整体替换为 `<NUM>` |
| 标识符 | 变量名/函数名/类名按出现顺序替换为 `ID1, ID2, ...`（**同程序同位置标识符映射一致**，这是关键：使"整体改名"无效） |
| 多字符运算符 | 作为独立 token 处理（如 `==`、`<=` 不被拆成 `=` `=`） |
| 支持语言 | `.java .py .c .h .cpp .cc .hpp .js .ts .go .cs .rs` |

> 说明：此处是"归一化 + 词法单元"层面的相似度，**不是 AST 归一化**。完整 AST（tree-sitter）需引入新依赖，列入第二轮。

#### 4.3.2 相似度合成

- **4-gram Jaccard**：在归一化后的 token 流上做 4-gram 集合交并比。
- **序列相似度**：`difflib.SequenceMatcher` 比例，捕捉整体结构一致性。
- **词频余弦**：token 词袋余弦。

#### 4.3.3 函数级匹配（可选，默认关闭）

`code.function_level.enabled` 开启后，按函数块切分，逐函数取最优来源，最终：

```
per_file_score = 0.4 × function_score + 0.6 × whole_file_score      （FUNCTION_WEIGHT=0.4 / WHOLE_FILE_WEIGHT=0.6）
structure_score = 各文件结构得分按文件长度加权平均
```

用于识别"只改函数名、保留内部实现"的抄袭。

#### 4.3.4 代码总分

`structure_score` 即上述加权平均，与文本管线的 `structure_score` 语义统一（均表示结构相似度），便于前端统一渲染。

### 4.4 比对范围与排除

| 库类型 | 语义 | 计分 |
| --- | --- | --- |
| `CLASS`（班级库，默认） | 同作业其他学生当前生效提交 | 计分 |
| 其他教师库 | 教师作业级勾选 | 计分 |
| `WHITELIST`（白名单库） | 教师维护的公共素材/模板 | **相似度 ≥ 0.90 的片段不计分**，仅输出到 `excludedItems` |

白名单库解决了"老师给了统一模板/框架代码，所有学生都被判抄袭"这一教学场景中的核心误判来源。

### 4.5 判定与等级

```
总分（0~100）
   ├─ < text_warning(20) / struct_warning(30)      → PASS（原创）
   ├─ ∈ [warning, severe)                          → WARNING（提示）
   └─ ≥ text_severe(50) / struct_severe(60)        → SEVERE（疑似抄袭，评审工作台强制置顶）
```

阈值可在 `system_config` 全局调整，也可在作业级 `check_config` 快照覆盖，**随作业固化不可事后改动**（防止"跑一遍看结果再调阈值"）。

### 4.6 队列与并发

| 机制 | 参数 |
| --- | --- |
| 任务抢占 | `SELECT ... FOR UPDATE SKIP LOCKED`，多 Worker 无中间件下安全抢占 |
| 租约 | `lease_seconds = 90` |
| 心跳 | `heartbeat_seconds = 20`，续租避免被误判为僵尸 |
| 轮询间隔 | `poll_seconds = 2.0` |
| 重试 | `max_attempts = 3`（= 最多 **3 次尝试**；`attempt >= max_attempts` → 永久 `FAILED`） |
| 退避 | 指数退避，`next_attempt_at` 控制重试时间 |
| **租约回收** | 每轮 `claim` 前调用 `reap_expired()`：租约过期任务回置 `QUEUED`；`requeue_count > 3` 转 `FAILED` 并告警管理员 |
| **重启恢复** | Worker 进程重启后，靠租约过期自动回收未完成任务，避免"进程崩溃 → 任务永久挂死" |
| **失败告警** | `CHECK_FAILED_ADMIN` 通知 + 监控指标 `checkFailureRate` |

### 4.7 报告不可变与留痕

- 报告内容 JSON 上传 S3，数据库仅存摘要 + 内容摘要（digest）+ 版本号。
- `is_current = true` 唯一索引保证同一提交仅一条当前报告；切换会保留历史版本（前端可切换查看）。
- 触发器保证报告落库后内容不可改（审计需要）。
- 事务回滚时清理孤儿报告对象（`storage.delete`）。
- 配置快照（阈值、开关、权重）随报告一起固化，报告可自证"当时按什么参数跑的"。

### 4.8 可选算法增强（默认关闭，不改变默认输出）

| 能力 | 参数 | 默认 | 作用 |
| --- | --- | --- | --- |
| MinHash + LSH | `lsh.num_hashes=128`，`lsh.num_bands=16`，`candidate_threshold=0.7`，`max_candidates=200` | **关** | 候选预筛，缓解 N×M 全量比对 |
| 中文 2-gram 分词 | `chinese_seg.enabled` | **关** | 降低单字切分误匹配 |
| 函数级匹配 | `code.function_level.enabled` | **关** | 识别"改名保留实现" |
| 文本分数权重 | `text_score_weights = {sentence:0.6, full:0.4}` | 生效 | 可覆盖总分校正 |

所有开关经 `normalize_config` 统一为单一规范结构，兼容 `snake_case` / `camelCase` 双键名快照，历史报告配置不会被误读。

### 4.9 已知局限（诚实披露）

| 局限 | 影响 | 处置 |
| --- | --- | --- |
| 无完整 AST 归一化 | "等价改写"（变量改名+重排）仍有漏判可能 | 已用标识符归一化 + 函数级匹配部分缓解；完整 AST 列入第二轮（需 `tree-sitter` 依赖评审） |
| 规模仍为 O(N×M) | 全量比对，大班级/大库有压力 | LSH 候选预筛已实现（默认关闭），开启后可显著降低 |
| 无预查重 | 学生提交后无法即时自查 | 列入第二轮 |
| 压缩包 / 混合模式未做 | ZIP 批量、文本+代码混合作业不受支持 | 列入第二轮 |
| 历届库未做 | 无法与往届作业比对 | 本轮明确排除 |
| 病毒扫描默认 PASS | 扫描状态机与协议已就绪，但未部署 ClamAV | 策略可配置，需部署后切 `REJECT` |

## 六、第二轮开发计划

### 6.1 目标

在首轮"能跑通主流程"的基础上，补齐**规模能力**（预查重、压缩包、混合模式、历届库）、**学术诚信治理**（申诉、匿名、互评、小组贡献）、**教学运营能力**（通知增强、公告、助教分配、作业附件、备份）与**工程质量**（AST、病毒扫描、测试与 CI 门禁），将 56 条 [R2] 需求中的核心 42 条落地。

### 6.2 优先级划分

| 级别 | 内容 | 建议周期 |
| --- | --- | --- |
| **P0（必做）** | ①预查重（提交即时比对，`subject_type='PRE_CHECK'`）②压缩包提交与逐文件分类 ③混合模式查重 ④AST 归一化（tree-sitter）⑤病毒扫描落地（ClamAV）⑥后端测试框架 + CI 门禁（`mvn verify` 含测试、前端 `vue-tsc`、JaCoCo 阈值） | 第 1~5 周 |
| **P1（重点）** | ⑦申诉流程（学生申诉 → 教师处理 → 重评）⑧截止日期延期申请 ⑨小组提交与成员贡献记录 ⑩匿名评审 ⑪学生互评 ⑫通知增强（截止提醒、邮件、偏好、模板）⑬助教分配表（`review_assignment`）⑭作业附件（教师端作业说明） | 第 6~9 周 |
| **P2（增强）** | ⑮历届库（`HISTORICAL`，教师指定、不计分只预警）⑯课程公告 ⑰运营看板 ⑱数据备份/导出 ⑲通知模板管理 ⑳移动端适配 | 第 10~12 周 |

### 6.3 关键技术点预判

| 方向 | 技术风险 | 应对 |
| --- | --- | --- |
| 预查重 | 同步等待会阻塞提交接口 | 复用现有 `check_task` 队列 + `subject_type` 区分，异步推送结果给前端轮询 |
| 压缩包 | ZIP 炸弹、嵌套、超大 | 解压上限（条目数/总字节/单文件字节/压缩比）、逐文件分类后分派 |
| AST 归一化 | 依赖体积与无 grammar 降级 | 先做依赖评审；grammar 缺失时降级到现有归一化路径 |
| 历届库 | 往届数据膨胀 | 独立库类型 + 教师显式勾选 + 候选上限控制 |
| 测试与 CI | 覆盖率门槛过低失去意义 | 先建设施，再逐步抬高阈值；CI 合入门禁（后端 `mvn verify`、前端 `vue-tsc`、引擎 `unittest`） |

### 6.4 验收标准

- 三端验证门保持常绿（后端编译/测试、前端类型检查、引擎单测）。
- P0 项均有可执行的端到端演示路径与回归测试。
- 所有新增数据库结构走 Flyway 迁移，可回滚评估。
