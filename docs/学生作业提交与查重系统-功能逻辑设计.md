# 学生作业提交与查重系统 — 功能逻辑设计

> 版本：v1.0　|　面向用户：学生 / 教师 / 系统管理员

---

## 0. 文档导读

本设计以"**功能逻辑闭环、业务体系成熟、用户体验流畅**"为目标，参考 Turnitin、知网查重、Gradescope、GitHub Classroom、中国大学 MOOC 作业模块等成熟系统的实践经验，围绕三类核心角色展开需求分析与功能建模，并给出核心业务流程、数据模型、权限模型与非功能性设计。

---

## 1. 系统概述

### 1.1 系统定位

面向高校教学场景的**作业全生命周期管理平台**，核心能力为"**提交 → 查重 → 评审 → 反馈 → 归档**"的闭环流转，同时支持文本类与代码类作业的原创性检测。

### 1.2 核心价值

| 维度 | 说明 |
|------|------|
| 对学生 | 一站式完成作业查看、提交、查重自查、成绩与反馈查看，流程透明可追溯 |
| 对教师 | 自动化查重减轻比对负担，结构化评审与批量打分提升效率，数据看板辅助教学反思 |
| 对管理员 | 统一用户/课程/权限治理，查重资源库与系统运行可观测，保障公平与合规 |

### 1.3 参考系统借鉴要点

| 参考系统 | 借鉴要点 |
|---------|---------|
| Turnitin | 分段高亮查重报告、相似度分级、来源追溯、排除引用/模板机制 |
| 知网/维普 | 文献库比对、跨届比对、阈值可配置 |
| Gradescope | 结构化评分量规(Rubric)、批量评审、成绩分布统计、申诉处理 |
| GitHub Classroom | 代码作业仓库自动分发、自动评测脚本、代码查重(MOSS 思路) |
| 中国大学 MOOC | 作业发布、截止时间、补交、互评、通知触达 |

## 2. 用户需求分析

### 2.1 学生角色需求

| 编号 | 需求 | 优先级 | 痛点/动机 |
|------|------|--------|-----------|
| S-01 | 查看课程下所有作业及要求、截止时间、提交状态 | P0 | 信息分散易遗漏 |
| S-02 | 多格式提交（文档/图片/代码压缩包/在线文本） | P0 | 作业形式多样 |
| S-03 | 多版本提交与版本回溯，以最后一次/指定版本为准 | P0 | 误传后无法纠正 |
| S-04 | 提交前**自查查重**（预查重），避免正式提交后被判定 | P0 | 担心查重不过 |
| S-05 | 实时查看提交状态（未提交/已提交/查重中/查重完成/已评审） | P0 | 状态不透明焦虑 |
| S-06 | 查看查重报告（相似度、高亮对比、来源列表） | P0 | 需了解扣分依据 |
| S-07 | 查看成绩、教师评语、评分量规明细 | P0 | 反馈是学习闭环关键 |
| S-08 | 对查重结果或成绩发起**申诉**，并查看处理结果 | P1 | 误判需要救济通道 |
| S-09 | 截止时间前**申请延期**，附理由，等待教师审批 | P1 | 突发情况无法按时 |
| S-10 | 小组作业：以小组身份提交，组内成员共享状态 | P1 | 协作场景 |
| S-11 | 消息通知（新作业、即将截止、查重完成、成绩发布、申诉回复） | P1 | 主动触达避免错过 |
| S-12 | 历史作业归档查看 | P2 | 复习参考 |

## 3. 系统功能模块设计

### 3.1 模块总览

```
学生作业提交与查重系统
├── M1  用户与权限模块
├── M2  课程管理模块
├── M3  作业管理模块
├── M4  提交管理模块
├── M5  查重引擎模块          ← 核心差异化能力
├── M6  评审与反馈模块
├── M7  申诉与延期模块
├── M8  通知模块
├── M9  统计分析模块
└── M10 系统管理模块
```

### 3.2 M1 用户与权限模块

**职责**：统一身份认证、角色管理、权限控制、组织架构维护。

| 子功能 | 说明 |
|--------|------|
| 认证登录 | 账号密码 / 统一身份认证(SSO) |
| 角色管理 | 预置学生/教师/管理员/助教四角色，支持自定义角色与权限点组合 |
| 用户管理 | CRUD + 批量导入(Excel) + 按院系/班级组织 + 账号停用启用 |
| 权限模型 | RBAC + 数据范围控制（教师只能管自己课程，学生只能看自己作业） |
| 个人中心 | 资料修改、密码修改、通知偏好、绑定邮箱/手机 |

### 3.3 M2 课程管理模块

| 子功能 | 说明 |
|--------|------|
| 课程创建 | 教师创建课程，填写名称/学期/院系/简介/封面；提交后管理员审核（可选） |
| 花名册管理 | 邀请码加入 / 批量导入 / 教务同步 / 学生退课；支持分班分组 |
| 助教管理 | 指定助教、分配评审范围（学号区间/随机/按小组） |
| 课程归档 | 学期结束后归档，归档课程只读，作业与成绩保留可查 |
| 课程设置 | 公告、评分规则说明、学术诚信声明（提交时勾选确认） |

### 3.4 M3 作业管理模块

| 子功能 | 说明 |
|--------|------|
| 作业发布 | 配置项见下表 |
| 作业编辑 | 截止前可编辑；截止后编辑需确认影响 |
| 作业状态机 | 草稿 → 已发布 → 进行中 → 已截止 → 评审中 → 已结束 |
| 查重参数 | 开关、模式(文本/代码)、阈值、比对库、排除规则 |
| 评分量规 | 多维度 Rubric（维度/分值/描述/等级），可复用模板 |
| 作业附件 | 教师上传题目附件、参考材料（参考材料可设为查重白名单） |

**作业配置项**：

| 配置项 | 取值 | 默认 |
|--------|------|------|
| 标题/要求/附件 | 文本+文件 | — |
| 允许的文件类型 | doc/docx/pdf/txt/zip/py/java... | 全部 |
| 单文件大小上限 | MB | 50MB |
| 截止时间 | datetime | — |
| 是否允许补交 | bool | 否 |
| 补交截止时间 | datetime | — |
| 允许多版本提交 | bool | 是 |
| 生效版本规则 | 最后一次 / 学生指定 / 最高分 | 最后一次 |
| 是否开启查重 | bool | 是 |
| 查重模式 | 文本 / 代码 / 混合 | 文本 |
| 相似度警告阈值 | % | 20% |
| 相似度严重阈值 | % | 50% |
| 比对库 | 本班库(默认必选,不可关) / 历届库 / 互联网库 / 文献库(教师可选) | 本班库 |
| 排除引用文献 | bool | 是 |
| 排除模板/公共代码 | bool | 是 |
| 是否允许自查预查重 | bool | 是 |
| 作业权重 | %（用于课程总成绩计算） | — |
| 是否小组作业 | bool | 否 |
| 是否互评 | bool | 否 |

### 3.5 M4 提交管理模块

| 子功能 | 说明 |
|--------|------|
| 提交作业 | 上传文件/在线文本；校验类型/大小/截止时间；记录版本号 |
| 多版本管理 | 每次提交生成新版本，保留全部历史；按生效规则确定参评版本 |
| 指定生效版本 | 学生可在截止前指定某历史版本为最终版 |
| 提交状态查询 | 未提交/已提交/查重中/查重完成/评审中/已评审 |
| 小组提交 | 组内任一成员提交即视为小组提交，全员共享状态与结果 |
| 迟交处理 | 截止后补交通道（若允许），标记迟交，可配置迟交扣分规则 |
| 提交校验 | 文件完整性校验、病毒扫描、格式转换预处理 |
| 学术诚信确认 | 首次提交勾选"本人独立完成"声明 |

**提交状态机**：

```
未提交 ──提交──▶ 已提交 ──触发查重──▶ 查重中 ──完成──▶ 查重完成
                    │                                       │
                    └────(查重失败/重试)────────────────────┘
                                                          │
查重完成 ──教师开始评审──▶ 评审中 ──提交成绩──▶ 已评审 ──发布──▶ 已结束
```

### 3.6 M5 查重引擎模块（核心）

**职责**：对提交内容进行原创性检测，生成结构化查重报告。支持文本类与代码类作业。

#### 3.6.1 查重流程

```
提交触发/手动重查
   │
   ▼
① 文档预处理  ── 格式转换(PDF/DOCX→纯文本)、编码统一、去格式
   │
   ▼
② 文本清洗    ── 去除引用标注(若排除)、去除模板/公共代码、分句/分段
   │
   ▼
③ 特征提取    ── 文本: N-gram + SimHash/MinHash 指纹
                  代码: AST 归一化 + Token 序列 + 结构指纹
   │  
   ▼
④ 比对库检索  ── 本班库(默认必选,学生互查) + 历届库/互联网库/文献库(教师可选)
                  倒排索引 + 局部敏感哈希快速初筛
   │
   ▼
⑤ 相似度计算  ── 句子级/段落级/全文级 三层粒度
                  文本: Jaccard + 余弦相似度
                  代码: 编辑距离 + AST 结构相似度
   │
   ▼
⑥ 报告生成    ── 相似度总分 + 分段高亮 + 来源列表 + 对比视图
   │
   ▼
⑦ 结果存储与通知 ── 报告持久化、状态回写、通知学生与教师
```

#### 3.6.2 查重模式

| 模式 | 算法 | 适用场景 |
|------|------|---------|
| 文本查重 | N-gram 分词 + SimHash 指纹 + Jaccard/余弦相似度 | 论文、报告、读后感 |
| 代码查重 | AST 归一化(去注释/变量名/格式) + Token 序列比对 + 结构指纹(MOSS 思路) | 编程作业 |
| 混合查重 | 文档中代码段与文本段分离后分别处理 | 含代码的技术报告 |

#### 3.6.3 查重报告内容

| 字段 | 说明 |
|------|------|
| 总相似度 | 百分比，红/黄/绿三级（由阈值决定） |
| 分段高亮 | 原文逐段标注，相似段高亮，点击跳转来源对比 |
| 来源列表 | 每条来源：来源类型(同学/历届/互联网/文献)、相似度、链接/出处 |
| 对比视图 | 左右双栏原文 vs 来源文本，逐句对照 |
| 排除项 | 已排除的引用/模板/公共代码清单（透明可追溯） |
| 查重时间/参数 | 算法版本、比对库、阈值，便于复现与申诉复核 |

#### 3.6.4 资源库管理

| 资源库 | 维护方式 |
|--------|---------|
| 本班库 | 本课程本学期所有已提交作业自动入库（查重后）；**默认必选且不可关闭，为学生提交互查的核心比对源** |
| 历届库 | 历学期作业归档入库，管理员可剔除；教师可选启用 |
| 互联网库 | 接入搜索引擎/网页爬虫比对（可选，受版权约束）；教师可选启用 |
| 文献库 | 对接知网/万方等；**默认不启用，须教师显式选择且授权后方可接入** |
| 白名单 | 教师上传的模板/公共代码/允许引用材料，查重时排除 |

#### 3.6.5 预查重（学生自查）

- 学生正式提交前可触发预查重（若教师允许），消耗个人查重配额
- 预查重报告仅学生可见，不计入正式记录，不污染比对库
- 配额管理：每作业预查重次数上限可配置（默认 3 次）

### 3.7 M6 评审与反馈模块

| 子功能 | 说明 |
|--------|------|
| 评审工作台 | 列表展示全班提交，支持按相似度/学号/状态排序与筛选 |
| 在线批注 | 文档在线预览 + 划线批注 + 批注定位回写 |
| Rubric 打分 | 逐维度打分，自动汇总总分；支持快捷键批量操作 |

| 评审任务分配 | 助教按学号区间/随机/按小组分配评审任务 |

### 3.8 M7 申诉与延期模块

| 子功能 | 说明 |
|--------|------|
| 延期申请 | 学生提交延期申请（理由+附件+期望截止），教师审批通过/驳回 |
| 延期生效 | 通过后该学生截止时间单独延长，状态标记"已延期" |
| 查重申诉 | 学生对查重结果或成绩发起申诉（理由+证据），教师/管理员复核 |
| 申诉处理 | 教师查看申诉、可重新查重/调整成绩、回复处理结论 |
| 申诉状态机 | 待处理 → 处理中 → 已通过/已驳回 |
| 申诉记录 | 全程留痕，作为学术诚信档案 |

| 日志审计 | 操作日志、登录日志、查重日志、敏感操作留痕、可导出 |
| 公告管理 | 系统公告发布、置顶、维护通知 |
| 备份恢复 | 定期备份 + 手动备份 + 恢复演练 |

## 4. 核心业务流程（闭环设计）

### 4.1 作业全生命周期主流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 教师发布  │───▶│ 学生提交  │───▶│ 自动查重  │───▶│ 教师评审  │───▶│ 成绩发布  │
│  作业    │    │  作业    │    │  引擎    │    │  打分    │    │  归档    │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
      │               │               │               │               │
      ▼               ▼               ▼               ▼               ▼
   通知学生      状态可查       生成报告       查看报告       通知学生
                                                              查看成绩
                                                                  │
                                                          ┌───────┴───────┐
                                                          ▼               ▼
                                                     满意结束         发起申诉
                                                                          │
                                                                          ▼
                                                                   教师复核处理
                                                                          │
                                                                          ▼
                                                                   调整成绩/维持
```

**闭环要点**：发布→提交→查重→评审→反馈→(申诉→复核)→最终归档，每个环节状态可追溯、可回退、可补救，形成完整业务闭环。

### 4.2 作业提交流程（详细）

```
学生进入作业详情页
   │
   ├─▶ 校验：是否在截止时间内？ ─否─▶ 是否允许补交？ ─否─▶ 提示已截止，引导申请延期
   │                                  └是─▶ 进入补交流程
   └是
   │
   ▼
选择提交方式：上传文件 / 在线文本 / 小组提交
   │
   ▼
校验：文件类型 ✓ / 大小 ✓ / 病毒扫描 ✓
   │
   ▼
首次提交？ ─是─▶ 弹出学术诚信声明，勾选确认
   │
   ▼
生成新版本号，存储文件，预处理(格式转换)
   │
   ▼
作业开启查重？ ─是─▶ 投入查重队列，状态=查重中
   │              └─▶ 查重完成后状态=查重完成，通知学生
   └否─▶ 状态=已提交
   │
   ▼
更新提交进度看板（教师侧实时刷新）
```

### 4.3 查重流程（异步队列）

```
提交入队 ──▶ Worker 消费
              │
              ▼
         ① 预处理(格式转换/文本提取)
         ② 清洗(去引用/去模板/分句)
         ③ 特征提取(指纹生成)
         ④ 比对库检索(倒排索引+LSH初筛→精排)
         ⑤ 三层相似度计算(句/段/全文)
         ⑥ 报告生成(高亮+来源+对比)
              │
              ├─成功─▶ 报告持久化，状态=查重完成，通知学生+教师(高风险提醒)
              └─失败─▶ 状态=查重失败，记录错误，自动重试3次，仍失败则告警管理员
```

**设计要点**：查重为耗时操作，采用异步队列解耦，支持并发与限流；查重失败有重试与告警，保证最终一致。

### 4.4 评审流程

```
教师进入评审工作台
   │
   ├─▶ 按相似度/状态/学号筛选与排序
   ├─▶ 查看提交内容 + 查重报告(内嵌)
   │
   ▼
在线批注(划线/标注) + Rubric 逐维度打分 + 填写评语
   │
   ▼
保存草稿 / 提交评审
   │
   ▼
(可选) 标记查重结论：确认原创 / 疑似抄袭 / 约谈处理
   │
   ▼
单份或批量发布成绩 ──▶ 状态=已评审，通知学生
```

### 4.5 申诉流程

```
学生查看查重报告/成绩 ──认为有误──▶ 发起申诉(理由+证据)
   │
   ▼
教师收到申诉通知 ──▶ 查看申诉详情
   │
   ├─▶ 可重新查重(调整参数) / 调整成绩 / 约谈学生
   │
   ▼
填写处理结论：通过(改判) / 驳回(维持) ──▶ 通知学生
   │
   ▼
申诉记录归档(学术诚信档案)
```

### 4.6 延期申请流程

```
学生(截止后/截止前) ──▶ 提交延期申请(理由+期望时间+附件)
   │
   ▼
教师审批 ─通过─▶ 该学生截止时间单独延长，状态标记"已延期"，通知学生
            ─驳回─▶ 通知学生，维持原截止时间
```

## 6. 用户体验设计要点

### 6.1 设计原则

| 原则 | 落地 |
|------|------|
| 状态透明 | 每一步都有明确状态与进度，消除"黑盒等待"焦虑 |
| 操作可逆 | 多版本、可指定生效版、可申诉、可延期，降低误操作代价 |
| 主动触达 | 关键节点通知触达，避免学生错过截止 |
| 渐进披露 | 详情按需展开，列表页信息精简，避免信息过载 |
| 一致性 | 三端(Web/移动)交互一致，术语统一 |

### 6.2 关键体验设计

| 场景 | 设计 |
|------|------|
| 学生提交页 | 一屏展示：作业要求(可展开) + 截止倒计时 + 提交区 + 历史版本列表 + 当前状态徽章 |
| 截止倒计时 | 临近截止(24h/1h)变色提醒，配合通知 |
| 查重报告 | 总分仪表盘(红黄绿) + 分段高亮原文 + 点击来源弹窗对比，无需跳转 |
| 教师评审台 | 左侧提交列表(可排序筛选) + 中间文档预览批注 + 右侧 Rubric 打分面板，三栏高效 |
| 提交进度看板 | 环形图已交/未交/迟交 + 名单表格 + 一键催交通知 |
| 错误预防 | 提交前预览、删除二次确认、发布成绩前预览影响范围 |

### 6.3 异常与边界处理

| 场景 | 处理 |
|------|------|
| 查重服务不可用 | 提交仍成功，查重状态置"排队/失败"，服务恢复后自动补查，不影响提交 |
| 文件格式不支持 | 提交时即时校验并提示，给出转换建议 |
| 截止瞬间提交 | 服务端以接收时间为准，前端倒计时与服务器校验一致 |
| 大文件上传 | 分片上传 + 断点续传 + 进度条 |
| 并发查重 | 队列 + 限流 + 优先级(正式提交>预查重) |
| 网络中断 | 草稿自动保存 + 提交幂等(防重复提交) |

## 8. 功能闭环与成熟度自检

### 8.1 闭环自检矩阵

| 业务环节 | 输入 | 输出 | 下游 | 闭环保证 |
|---------|------|------|------|---------|
| 发布 | 教师配置 | 作业+通知 | 学生可见 | 状态机驱动 |
| 提交 | 学生文件 | 版本记录 | 触发查重 | 状态回写+通知 |
| 查重 | 提交内容 | 查重报告 | 教师评审 | 异步队列+重试+告警 |
| 评审 | 报告+内容 | 成绩+评语 | 成绩发布 | 草稿/发布两段式 |
| 反馈 | 成绩 | 学生可见 | 学生查看 | 发布触发通知 |
| 申诉 | 学生异议 | 复核结论 | 成绩调整 | 申诉状态机+留痕 |
| 归档 | 学期结束 | 历史库 | 下届查重库 | 归档只读+入库 |

## 9. 总结

本设计以"**提交→查重→评审→反馈→(申诉)→归档**"为主干闭环，通过状态机驱动各环节流转，保证业务逻辑自洽与可追溯。三类角色需求分层覆盖：学生侧重**透明易用与可补救**，教师侧重**自动化减负与高效评审**，管理员侧重**全局治理与可观测**。查重引擎作为核心差异化能力，支持文本/代码双模式、多比对库、分段高亮报告与可配置阈值，并通过异步队列保证可靠性。整体设计在功能闭环、异常处理、用户体验与非功能性指标上对标成熟系统，具备可落地实施的成熟度。
