## 1\. 引言

### 1.1 目的

本需求规格说明书旨在完整、准确地描述学生作业提交与查重系统的功能需求、非功能需求、外部接口需求与业务规则，为系统的架构设计、详细设计、编码实现、测试验收以及项目验收评审提供需求基线。

本文档的预期读者包括：项目甲方（教务管理部门）、系统分析与设计人员、开发工程师、测试工程师、项目管理人员以及系统最终用户代表（学生、教师、系统管理员）。不同读者可按需关注相应章节：甲方与项目管理员关注第 2 章总体描述与第 3.3 节功能需求摘要；设计与开发人员关注第 3 章全部需求规格；测试人员关注第 3 章可测试的需求条目与第 4 章验收标准。

### 1.2 范围

本系统面向高校教学场景，提供作业从发布、提交、原创性查重、教师评审、成绩反馈到申诉归档的全生命周期管理能力。系统支持文本类作业（论文、报告等）与代码类作业（编程作业）两种查重模式，服务于学生、教师、助教、系统管理员四类用户角色。

系统包含十大功能模块：用户与权限管理、课程管理、作业管理、提交管理、查重引擎、评审与反馈、申诉与延期、通知、统计分析、系统管理。其中查重引擎为系统的核心差异化能力。

本系统不包含：教务系统本身的选课与排课功能（通过接口对接）、在线考试功能、视频直播教学功能。上述能力由外部教务系统或第三方教学平台提供，本系统仅通过接口集成。

## 2\. 总体描述

### 2.1 产品视角

本系统是一个独立运行的 Web 应用系统，采用前后端分离架构，前端提供浏览器访问界面，后端提供 RESTful API 服务。系统不隶属于某一现有教务系统，但需要与教务系统进行数据集成。

系统与外部实体的关系如下：

```
                    ┌─────────────────┐
                    │   教务系统       │
                    │ (选课/学籍/成绩) │
                    └────────┬────────┘
                             │ 同步接口
                             ▼
┌──────────┐         ┌─────────────────┐         ┌──────────┐
│ 统一身份  │──SSO──▶│  本系统          │◀──文件──│  对象存储  │
│ 认证服务  │         │ (作业提交查重)   │         │  服务     │
└──────────┘         └────────┬────────┘         └──────────┘
                             │
              ┌──────────────┼──────────────┐
              ▼              ▼              ▼
        ┌──────────┐  ┌──────────┐  ┌──────────┐
        │ 查重引擎  │  │ 通知服务  │  │ 文献/搜索 │
        │ (内置)   │  │(邮件/短信)│  │ 比对源(可选)│
        └──────────┘  └──────────┘  └──────────┘

```

系统内部由前端应用层、API 网关层、业务服务层（用户服务、课程服务、作业服务、提交服务、查重服务、评审服务、通知服务）、查重引擎层（文本查重、代码查重、压缩包处理、比对库管理）、异步任务队列层与数据持久层组成。

系统提供以下主要功能类别，详细需求见第 3.2 节。

| 编号 | 功能类别 | 简述 |
| --- | --- | --- |
| F-01 | 用户与权限管理 | 身份认证、角色与权限控制、用户与组织维护 |
| F-02 | 课程管理 | 课程创建、花名册维护、助教管理、课程归档 |
| F-03 | 作业管理 | 作业发布与配置、查重参数设置、评分量规定义 |
| F-04 | 提交管理 | 多格式多版本提交、状态跟踪、小组提交、迟交处理 |
| F-05 | 查重引擎 | 文本/代码查重、压缩包代码查重、报告生成、资源库管理、预查重 |
| F-06 | 评审与反馈 | 在线批注、量规打分、批量操作、成绩发布 |

### 2.3 用户类与特征

系统识别四类用户角色，各类用户的特征、使用频率与关键需求如下。

**学生**：系统的主要使用者，人数最多（单系统可达数万量级），计算机操作熟练度参差不齐。学生通过系统查看作业要求、提交作业、查看查重报告与成绩反馈。使用场景集中在作业截止前的高峰时段，对操作简便性、状态透明性和反馈及时性要求高。学生只能访问本人所修课程的作业与本人提交记录，不能查看其他学生的提交内容与成绩。

**教师**：课程的创建者与作业的管理者，负责发布作业、配置查重参数、评审打分、处理申诉与延期。教师对系统的专业功能（如查重参数配置、量规设计、批量操作）有较高要求，使用频率随教学周期波动，评审期集中使用。教师只能管理本人创建或被授权的课程，可查看本课程全部学生的提交、查重报告与成绩。

**助教**：由教师授权，协助评审。助教仅能查看与评审教师分配范围内的学生提交，不能修改作业配置、不能发布成绩、不能处理申诉。助教权限是教师权限的受限子集。

**系统管理员**：负责系统全局配置、用户与权限治理、查重资源库维护、系统监控与运维。管理员不参与具体教学业务，但保障系统正常运行与数据合规。管理员可访问系统全局数据，但受审计约束，敏感操作留痕。

### 2.4 运行环境

**客户端**：支持主流浏览器（Chrome 90+、Edge 90+、Firefox 88+、Safari 14+），支持桌面端与平板端响应式布局；移动端提供适配页面或可选原生 App。

**服务端**：部署于 Linux 服务器，后端运行于 JVM 或 Node.js 运行时；数据库采用关系型数据库（MySQL 8.0+ 或 PostgreSQL 13+）；文件存储采用对象存储服务（如 MinIO/OSS）；查重任务队列采用消息中间件（如 RabbitMQ/Redis Queue）；缓存采用 Redis。

**网络环境**：校园网与公网均可访问，传输采用 HTTPS 加密；查重引擎与比对库部署于同一内网以降低比对延迟。

### 2.5 设计与实现约束

-   **C-01**：系统须与学校统一身份认证系统对接，支持 SSO 登录，不自行维护密码策略时遵循学校统一策略。
-   **C-02**：学生成绩数据须能导出为教务系统可接收的格式（Excel/CSV），并符合教务系统字段规范。
-   **C-03**：查重引擎的算法实现须可插拔替换，以支持后续算法升级而不影响业务层。
-   **C-04**：上传文件须经过病毒扫描，禁止可执行文件直接存储与分发。
-   **C-05**：系统须遵循《个人信息保护法》，学生个人数据仅用于教学业务，不得未授权共享。
-   **C-06**：查重报告须保留算法版本与参数，保证结果可复现，以支撑申诉复核。
-   **C-07**：系统界面语言为中文，架构上支持国际化扩展。
-   **C-08**：压缩包解压须在沙箱隔离环境中执行，限制最大解压体积与文件数量，防止 Zip Bomb 攻击。

### 2.6 假设与依赖

-   **A-01**：假设学校统一身份认证服务可用且提供标准接口（CAS/OAuth2.0）。
-   **A-02**：假设教务系统能提供选课关系与学籍基础数据，或由管理员手动批量导入。
-   **A-03**：假设历届作业库已由管理员完成入库，或允许系统在运行过程中逐步积累。
-   **A-04**：假设互联网比对源（若启用）的访问受版权协议约束，仅返回相似度与出处链接，不存储原文。
-   **A-05**：依赖对象存储服务的高可用性，文件上传后不丢失。
-   **A-06**：依赖消息队列的持久化能力，查重任务在服务重启后可恢复执行。
-   **A-07**：假设代码查重所需的语言解析器（Java/Python/C/C++/JavaScript/Go 等）可集成或自行实现 AST 解析。

## 3\. 需求规格

### 3.1 外部接口需求

#### 3.1.1 用户界面需求

系统用户界面须满足以下要求：

-   **UI-01**：采用响应式 Web 设计，在 1280×720 及以上分辨率正常显示，平板端自适应布局。
-   **UI-02**：全局导航栏区分学生、教师、管理员工作台入口，按当前用户角色显示可见功能。
-   **UI-03**：所有表单提交须有前端校验与明确错误提示，禁止静默失败。
-   **UI-04**：长列表须支持分页、排序、筛选，单页默认 20 条，可切换 50/100。
-   **UI-05**：文件上传须显示进度条，大文件支持分片上传与断点续传。
-   **UI-06**：查重报告页以仪表盘展示总相似度（红/黄/绿三色），下方分段高亮原文，点击高亮段弹出来源对比双栏视图。
-   **UI-07**：教师评审工作台采用三栏布局：左侧提交列表、中间文档预览与批注、右侧评分量规面板。
-   **UI-08**：所有不可逆操作（删除、成绩发布、批量操作）须二次确认。
-   **UI-09**：关键状态（提交状态、查重状态、评审状态）以彩色徽章标识，全系统统一语义。
-   **UI-10**：截止时间以倒计时显示，临近截止（24 小时内）变色提醒。
-   **UI-11**：代码查重报告须展示文件分类清单，标注每个文件的分类桶（参与查重/已排除）与排除原因，支持教师点击查看完整文件列表。

#### 3.1.2 软件接口需求

| 编号 | 接口 | 方向 | 协议/格式 | 说明 |
| --- | --- | --- | --- | --- |
| SI-01 | 统一身份认证 | 本系统→认证服务 | CAS/OAuth2.0 | SSO 登录与令牌校验 |
| SI-02 | 教务数据同步 | 教务系统→本系统 | RESTful/JSON | 同步选课关系、学籍信息 |
| SI-03 | 成绩回传 | 本系统→教务系统 | RESTful/JSON 或文件 | 课程结束后成绩导出/推送 |
| SI-04 | 对象存储 | 本系统→存储服务 | S3 兼容协议 | 文件上传/下载/删除 |
| SI-05 | 消息队列 | 本系统内部 | AMQP | 查重任务异步分发 |
| SI-06 | 邮件服务 | 本系统→邮件网关 | SMTP | 通知邮件发送 |
| SI-07 | 短信服务 | 本系统→短信网关 | HTTP API | 通知短信发送（可选） |
| SI-08 | 文献比对源 | 本系统→文献库 | 专有 API | 文献相似度比对（可选） |

#### 3.1.3 硬件接口需求

无特殊硬件接口需求。系统为纯软件系统，运行于标准服务器硬件之上。若启用纸质作业扫描上传场景，须支持通用扫描仪通过浏览器 TWAIN/WIA 接口上传，此为可选需求。

#### 3.1.4 通信接口需求

-   **CI-01**：客户端与服务端之间采用 HTTPS（TLS 1.2+）加密通信。
-   **CI-02**：服务间内部通信可采用 HTTP/gRPC，部署于内网环境。
-   **CI-03**：文件上传支持分片传输，单片默认 5MB，支持断点续传。
-   **CI-04**：查重报告等大数据量接口支持分页与按需加载。

### 3.2 功能需求

本节按功能模块组织，每条功能需求给出唯一编号、优先级、描述、输入、输出、前置条件与后置条件。需求编号格式为 FR-<模块>-<序号>。

#### 3.2.1 用户与权限管理（FR-U）

**FR-U-01 用户登录（P0）**

用户通过统一身份认证或账号密码登录系统。系统验证用户身份与账号状态，成功后建立会话并加载角色权限；失败时返回明确错误原因并记录登录日志。连续登录失败 5 次锁定账号 30 分钟，锁定期间需管理员解锁或等待自动解锁。

-   输入：用户名/学工号、密码或 SSO 令牌
-   输出：登录成功返回会话令牌与用户信息；失败返回错误码
-   前置条件：用户账号存在且处于启用状态
-   后置条件：成功时创建会话并记录登录日志；失败时累计失败次数

**FR-U-02 用户登出（P0）**

用户主动登出，系统销毁当前会话令牌，跳转登录页。

**FR-U-03 用户信息维护（P0）**

用户在个人中心修改本人资料（姓名、邮箱、手机、头像）与密码。修改密码须验证原密码。学工号与角色不可由用户自行修改。

**FR-U-04 用户管理（管理员，P0）**

管理员对用户进行增删改查操作，支持按姓名/学工号/角色/院系/状态搜索与分页。支持通过 Excel 批量导入用户（含学工号、姓名、邮箱、角色、院系、班级），导入时校验学工号唯一性，重复记录跳过并报告。管理员可启用/停用用户账号、重置密码。停用账号立即失效其活跃会话。

**FR-U-05 角色与权限管理（P0）**

系统预置学生、教师、助教、管理员四类角色，每类角色绑定一组权限点。管理员可查看角色权限矩阵，可创建自定义角色并分配权限点。权限控制采用 RBAC 模型叠加数据范围控制：教师仅能操作本人课程，学生仅能操作本人数据，助教仅能操作分配范围内数据。

**FR-U-06 组织架构管理（P1）**

管理员维护院系、专业、班级的组织树，用户归属组织节点。组织信息用于用户筛选、数据范围控制与统计维度。

#### 3.2.2 课程管理（FR-C）

**FR-C-01 课程创建（P0）**

教师创建课程，填写课程名称、课程代码、学期、院系、简介、封面图片。课程创建后处于"待审核"或直接"已激活"状态（由系统配置决定是否需要管理员审核）。课程代码在同一学期内唯一。

-   输入：课程名称、课程代码、学期、院系、简介、封面
-   输出：课程记录，创建者自动成为课程负责人
-   前置条件：用户角色为教师或管理员
-   后置条件：课程创建成功，创建者获得该课程管理权限

**FR-C-02 课程编辑与归档（P0）**

教师可编辑本人课程的基本信息。学期结束后可将课程归档，归档后课程及其作业、提交、成绩变为只读，但保留可查询。管理员可强制归档任意课程。

**FR-C-03 花名册管理（P0）**

教师维护课程学生花名册，支持三种方式：生成邀请码由学生自助加入、Excel 批量导入学号、从教务系统同步选课名单。支持学生退课（移除花名册）。花名册变更记录留痕。

**FR-C-04 助教管理与评审任务分配（P1）**

教师为课程指定助教（须为系统注册用户），并分配评审范围。分配方式包括：按学号区间、随机分配 N 份、按小组分配。助教仅能查看与评审分配范围内的提交。教师可随时调整或撤销助教权限。

**FR-C-05 课程公告（P1）**

教师发布课程公告，公告在课程主页置顶展示并通知全体学生。支持公告编辑与删除。

#### 3.2.3 作业管理（FR-A）

**FR-A-01 作业发布（P0）**

教师在课程下发布作业，配置以下属性：标题、内容要求、题目附件、允许的文件类型、单文件大小上限、截止时间、是否允许补交及补交截止时间、是否允许多版本提交及生效版本规则、是否开启查重及查重参数、作业权重、是否小组作业、是否互评、评分量规。作业发布前可保存为草稿。发布后学生可见，触发通知。

-   输入：作业配置项全集
-   输出：作业记录，状态为"已发布"
-   前置条件：用户为该课程教师，课程处于激活状态
-   后置条件：作业对学生可见，通知触达花名册学生

**FR-A-02 作业编辑（P0）**

教师可编辑已发布作业的配置项。截止时间前编辑不影响已提交内容；截止时间后编辑须二次确认并提示影响范围。查重参数变更后，对已生成查重报告的提交须提示是否重新查重。

**FR-A-03 作业状态流转（P0）**

作业状态按以下状态机流转：草稿 → 已发布 → 进行中（到达发布后、截止前）→ 已截止 → 评审中（教师开始评审）→ 已结束（成绩发布且申诉期过）。状态流转由系统根据时间与操作自动驱动，教师可手动推进评审阶段。

**FR-A-04 查重参数配置（P0）**

教师在作业配置中设置查重参数：查重模式（文本/代码/混合）、相似度警告阈值、相似度严重阈值、比对库选择、是否排除引用文献、是否排除模板与公共代码、是否允许学生预查重及预查重次数上限。其中比对库选择规则为：**本班库（本课程学生提交作业之间的互同比对）默认开启且不可关闭，为查重核心比对源**；历届库、互联网库、文献库由教师按需多选启用，**文献库（对接知网/万方等）默认不启用，须教师显式勾选且须有授权方可生效**。对于代码查重模式，教师还可配置压缩包查重文件范围（见 FR-K-14）。参数须在作业发布时确定，发布后修改须确认影响。

**FR-A-05 评分量规定义（P0）**

教师为作业定义评分量规（Rubric），量规由多个评分维度组成，每个维度包含名称、满分值与若干等级描述（如"优秀/良好/合格/不合格"及对应分值区间与描述）。量规可保存为模板供其他作业复用。评审时教师逐维度打分，系统自动汇总总分。

**FR-A-06 作业附件与参考材料（P1）**

教师上传题目附件与参考材料。参考材料可标记为"查重白名单"，标记后其中的内容在查重时自动排除，避免学生引用教师提供的材料而被误判。

#### 3.2.4 提交管理（FR-S）

**FR-S-01 作业提交（P0）**

学生在作业详情页提交作业，支持上传文件（一种或多种允许类型）或在线填写文本。系统校验文件类型、大小、截止时间。首次提交时须勾选学术诚信声明（"本人独立完成"）。提交成功后生成新版本号，存储文件并触发预处理（格式转换）。若作业开启查重，提交后自动投入查重队列。

-   输入：文件或在线文本
-   输出：提交记录（含版本号、提交时间、状态）
-   前置条件：学生在花名册内，作业处于可提交状态（进行中或允许补交）
-   后置条件：提交记录创建，若开启查重则查重任务入队，教师进度看板更新

**FR-S-02 多版本提交与生效版本（P0）**

当作业允许多版本提交时，学生每次提交生成新版本，系统保留全部历史版本。生效版本按配置规则确定：最后一次提交、学生手动指定、或最高分版本（评审后确定）。学生可在截止时间前手动指定某一历史版本为生效版本。查重与评审均针对生效版本执行。

**FR-S-03 提交状态查询（P0）**

学生可实时查看本人每次提交的状态：未提交、已提交、查重中、查重完成、查重失败、评审中、已评审。状态以徽章标识，查重中显示排队进度。

**FR-S-04 小组提交（P1）**

当作业为小组作业时，组内任一成员提交即视为小组提交，全体成员共享提交状态、查重报告与成绩。系统记录实际提交人。小组成员由教师或学生组长维护。

**FR-S-05 迟交处理（P0）**

学生超过截止时间提交时，若作业允许补交且在补交截止时间内，提交成功但标记为"迟交"。迟交可配置扣分规则（如迟交每日扣 X 分或按比例扣分），在成绩计算时自动应用。若不允许补交，提示已截止并引导申请延期。

**FR-S-06 提交文件校验（P0）**

系统对上传文件执行以下校验：文件类型在允许列表内、文件大小不超过上限、文件未携带病毒（调用病毒扫描）、文件可正常解析（如 PDF 未损坏）。任一校验失败则拒绝提交并返回明确原因。

#### 3.2.5 查重引擎（FR-K）

**FR-K-01 文本查重（P0）**

对文本类作业执行原创性检测。默认以本班库（本课程学生提交作业之间）为核心比对源进行互同比对，若教师额外启用历届库/互联网库/文献库则一并纳入比对。处理流程为：文档预处理（PDF/DOCX 转纯文本、编码统一）→ 文本清洗（按配置去除引用标注、模板与公共代码）→ 分句分段 → 特征提取（N-gram 分词生成 SimHash/MinHash 指纹）→ 比对库检索（本班库必查，其余按教师选择，倒排索引与局部敏感哈希初筛后精排）→ 相似度计算（句子级、段落级、全文级三层粒度，采用 Jaccard 与余弦相似度）→ 报告生成。

-   输入：提交的文本内容、查重参数、比对库
-   输出：查重报告（总相似度、分段高亮、来源列表、对比视图、排除项、算法版本与参数）
-   前置条件：提交内容已预处理
-   后置条件：报告持久化，提交状态置"查重完成"，通知学生与教师（高风险提醒）

**FR-K-02 代码查重（P0）**

对代码类作业执行原创性检测。处理流程为：源码解析 → AST 归一化（去除注释、统一变量名、规范化格式）→ Token 序列提取 → 结构指纹生成（借鉴 MOSS 思路）→ 比对库检索 → 相似度计算（编辑距离与 AST 结构相似度）→ 报告生成。代码查重须忽略语法等价但书写风格不同的差异，聚焦逻辑结构相似性。

当学生提交的是可运行系统的代码文件压缩包（含纯代码文件、可运行文件、测试脚本、第三方依赖等混合内容）时，须按 FR-K-10 至 FR-K-15 规定的压缩包代码查重流程执行：先解压并安全校验，再对文件分类过滤，仅对核心源码执行归一化与分层查重，最后聚合报告并标注文件分类清单。

**FR-K-03 混合查重（P1）**

对含代码段与文本段的技术报告，自动识别并分离代码段与文本段，分别采用代码查重与文本查重，最后合并报告。

**FR-K-04 查重报告生成（P0）**

查重完成后生成结构化报告，包含：总相似度百分比（按阈值标红/黄/绿）、分段高亮（原文逐段标注相似段）、来源列表（每条来源含类型、相似度、出处链接）、左右双栏对比视图、已排除项清单（引用、模板、公共代码）、查重时间与算法版本与参数（用于复现）。报告以 HTML 与 JSON 双格式存储，HTML 供在线查看，JSON 供程序读取。

对于压缩包代码查重，报告还须包含文件分类清单（见 FR-K-15）。

**FR-K-05 查重任务队列（P0）**

查重为耗时操作，采用异步消息队列解耦。提交触发查重时任务入队，Worker 消费执行。队列支持优先级（正式提交高于预查重）、并发控制与限流。任务失败自动重试最多 3 次，仍失败则标记"查重失败"并告警管理员，不影响提交本身的有效性。服务重启后队列中未完成任务可恢复执行。

**FR-K-06 预查重（学生自查，P0）**

当作业允许预查重时，学生可在正式提交前对草稿内容执行预查重。预查重报告仅学生本人可见，不计入正式查重记录，不将内容写入比对库。每位学生每作业预查重次数受上限约束（默认 3 次），超限提示。预查重消耗后配额递减，配额由作业配置决定。

**FR-K-07 手动重查（P0）**

教师可对单份或批量提交手动触发重新查重，用于查重失败恢复、参数调整后复查或申诉复核场景。重查生成新版本报告，旧报告归档保留。

**FR-K-08 比对库管理（P0）**

系统维护四类比对库：本班库（本课程本学期已提交作业，查重后自动入库，为默认且不可关闭的核心比对源，实现学生提交之间的互同比对）、历届库（历学期归档作业入库，管理员可剔除，教师可选启用）、互联网库（接入搜索引擎/网页比对，可选，教师可选启用）、文献库（对接知网/万方等，默认不启用，须教师显式选择且须有授权方可生效）。管理员可管理各库的入库、剔除与状态。教师上传的参考材料可加入白名单库，查重时排除。

**FR-K-09 查重结果分级与预警（P0）**

根据相似度与阈值分级：低于警告阈值为"通过"（绿色），介于警告与严重阈值之间为"警告"（黄色），超过严重阈值为"严重"（红色）。严重级提交在教师评审工作台置顶预警，并通知教师。分级仅作辅助提示，最终判定由教师人工确认。

**FR-K-10 压缩包解压与安全校验（P0）**

当学生提交的代码作业为压缩包格式（.zip / .tar.gz / .rar 等）时，系统在沙箱隔离环境中执行解压，并进行安全校验，防止恶意压缩包耗尽系统资源。

处理流程为：压缩包大小校验（≤ 全局配置上限，默认 100MB）→ 沙箱解压 → 解压后总大小校验（≤ 500MB，防 Zip Bomb）→ 文件数量校验（≤ 10000 个）→ 路径穿越检测（拒绝含 `../` 的路径）→ 嵌套压缩递归解压（最多 3 层）→ 输出解压后文件清单。

-   输入：压缩包文件
-   输出：解压后文件清单（路径、大小、类型）
-   前置条件：压缩包已上传并通过病毒扫描
-   后置条件：解压成功则文件清单传递给 FR-K-11 分类；任一校验失败则拒绝并返回明确原因
-   异常处理：解压超时（默认 60 秒）终止并标记"解压失败"；校验失败记录日志并通知学生

**FR-K-11 文件分类与过滤（P0）**

对解压后的文件清单按用途归入六个分类桶，查重时仅对核心源码桶（A）和配置构建桶（B）执行比对，其余桶排除或按教师配置处理。

| 桶 | 类别 | 典型文件 | 查重处理 | 权重 |
| --- | --- | --- | --- | --- |
| A | 核心源码 | .java .py .c .cpp .h .js .ts .go .rs .cs .rb .php .kt .scala | 参与查重 | 1.0 |
| B | 配置与构建 | pom.xml build.gradle package.json Makefile application.yml .env Dockerfile | 参与查重 | 0.3 |
| C | 测试脚本 | *Test.java *test.py test_*.py *.spec.js conftest.py __tests__/* | 默认排除，教师可开启 | 0.5 |
| D | 第三方依赖 | node_modules/ vendor/ venv/ __pycache__/ .m2/ .gradle/ dist/ build/ target/ | 排除 | — |
| E | 二进制与资源 | .exe .dll .jar .class .so .o .pyc .png .jpg .mp3 .mp4 .zip .pdf .dat | 排除，仅记录清单 | — |
| F | 文档与说明 | README.md .txt .docx .pdf(文档) | 排除，仅记录清单 | — |

分类规则按优先级执行：（1）路径优先——文件路径中包含第三方依赖目录名（如 node_modules、vendor、target 等）则归入 D 桶；（2）测试脚本模式匹配——文件名匹配测试脚本命名模式则归入 C 桶；（3）扩展名映射——按扩展名映射表归入对应桶；（4）大文件降级——超过 10MB 的非源码文件归入 E 桶；（5）未知扩展名归入 F 桶。

-   输入：解压后文件清单
-   输出：分类结果（每文件标注桶类别、是否参与查重、排除原因）
-   前置条件：压缩包已成功解压（FR-K-10 完成）
-   后置条件：分类结果传递给 FR-K-12 归一化与 FR-K-13 分层查重

**FR-K-12 代码归一化预处理（P0）**

对 Bucket A（核心源码）中的每个源码文件执行归一化预处理，消除无关差异，聚焦逻辑结构相似性。归一化步骤包括：

| 步骤 | 作用 | 示例 |
| --- | --- | --- |
| 去除注释 | 消除注释差异 | `// 用户登录` → 删除 |
| 去除空行 | 消除排版差异 | 连续空行压缩为 0 |
| 标识符统一化 | 消除变量名重命名 | `userName`/`xm`/`stu_name` → `VAR_1` |
| 字符串字面量替换 | 消除字符串内容差异 | `"张三"` → `STR_1` |
| 数字字面量替换 | 消除魔法数差异 | `100` → `NUM_1` |
| 缩进统一 | 消除缩进风格差异 | Tab → 4 空格 |
| import 排序 | 消除导入顺序差异 | 按字母序排列 |

归一化处理须保留原始文件与归一化后文件的映射关系，用于后续报告中的高亮定位。对 Bucket B（配置构建文件）不执行归一化，直接参与文本级比对。

-   输入：Bucket A 源码文件集合
-   输出：归一化后代码集合 + 原始映射关系
-   前置条件：文件分类完成（FR-K-11 完成）
-   后置条件：归一化代码传递给 FR-K-13 分层查重

**FR-K-13 分层查重比对（P0）**

对归一化后的代码执行三层查重，逐层细化，兼顾召回率与精度：

| 层级 | 算法 | 粒度 | 输出 | 作用 |
| --- | --- | --- | --- | --- |
| Layer 1 文本指纹层 | SimHash / MinHash | 文件级 | 相似文件对候选集 | 快速初筛，高召回率 |
| Layer 2 结构指纹层 | AST 子树哈希 + 树编辑距离 | 函数/方法级 | 结构相似函数对 | 抗重命名、抗语句重排，检测改写抄袭 |
| Layer 3 语义指纹层 | N-gram + Rabin-Karp 滑动匹配 | 代码块级（连续 N 行） | 精确匹配代码片段位置 | 提供可视化证据，支撑人工复核 |

分层策略：Layer 1 快速过滤明显不相似的文件对，避免后续层浪费算力；Layer 2 是检测"改写抄袭"的核心，抗重命名与语句重排；Layer 3 提供精确的可视化证据。三层结果聚合后生成最终相似度评分与匹配详情。

对 Bucket B（配置构建文件），仅执行 Layer 1 文本指纹层比对，结果按 0.3 权重计入总相似度。

-   输入：归一化代码集合（Bucket A）+ 配置文件集合（Bucket B）+ 比对库
-   输出：分层查重结果（文件级相似度、函数级结构相似度、代码块级匹配位置）
-   前置条件：归一化预处理完成（FR-K-12 完成）
-   后置条件：查重结果传递给 FR-K-04 报告生成

**FR-K-14 查重文件范围配置（P0）**

教师可在作业查重参数中配置压缩包代码查重的文件范围，按作业特点灵活调整：

-   **参与查重的桶**：默认为 A + B，教师可增减
-   **是否包含测试脚本**：默认否（Bucket C 默认排除），教师可开启
-   **额外排除路径模式**：教师可自定义 glob 模式排除特定目录或文件（如 `examples/*`、`demo/*`）
-   **相似度阈值**：文本相似度与结构相似度分别设置告警阈值与标记阈值
-   **归一化选项**：教师可开关各归一化步骤（如保留注释差异、不统一标识符等）

配置以 YAML 格式存储，作为作业查重参数的子配置。未显式配置时使用系统默认值。

-   输入：教师查重文件范围配置
-   输出：查重配置记录（关联作业）
-   前置条件：教师为该作业所在课程负责人
-   后置条件：配置生效，后续查重任务按此配置执行

**FR-K-15 查重报告文件清单标注（P1）**

压缩包代码查重报告须包含文件分类清单，让教师与学生了解每个文件的处理情况：

-   **总览统计**：提交文件总数、参与查重文件数（分桶统计）、排除文件数（分桶统计）、整体最大相似度
-   **文件清单**：逐文件标注分类桶、是否参与查重、排除原因（如"第三方依赖"、"二进制资源"、"测试脚本-已排除"）
-   **相似度详情**：对参与查重的文件对，分别展示文本相似度、结构相似度、匹配代码块数量，支持点击查看归一化后对比视图与高亮匹配段
-   **教师复核建议**：结构相似度超过 70% 的文件对建议人工复核

-   输入：分层查重结果 + 文件分类结果
-   输出：含文件清单的查重报告
-   前置条件：分层查重完成（FR-K-13 完成）
-   后置条件：报告持久化，提交状态置"查重完成"

#### 3.2.6 评审与反馈（FR-R）

**FR-R-01 评审工作台（P0）**

教师进入评审工作台，以列表展示全班提交，支持按相似度、学号、提交时间、状态排序与筛选。列表显示学生姓名、提交时间、相似度、评审状态。点击进入单份评审详情。

**FR-R-02 在线批注（P0）**

教师在文档在线预览界面进行划线批注，批注内容定位回写到文档对应位置。批注支持文本批注，可选语音批注（自动转文字）。学生查看反馈时可看到带批注的文档。

**FR-R-03 量规打分（P0）**

教师按评分量规逐维度打分，每个维度选择等级或输入分值，系统自动汇总总分。支持快捷键操作以提升效率。打分可保存为草稿（学生不可见）或提交（进入待发布状态）。

**FR-R-04 评语与反馈附件（P0）**

教师填写总体评语（文本），可上传反馈附件（如批改后的文档）。评语与附件在成绩发布后对学生可见。

**FR-R-05 查重结论标记（P0）**

教师在评审时查看内嵌的查重报告，可对查重结论做出人工判定标记：确认原创、疑似抄袭、约谈处理。标记结果记入评审记录，疑似抄袭与约谈处理触发学术诚信档案记录。

**FR-R-06 批量操作（P0）**

教师可执行批量操作：批量打分（按规则赋分，如全部满分、按相似度自动扣分）、批量下载提交文件（打包 ZIP）、批量重新查重、批量发布成绩。批量操作须二次确认并预览影响范围。

**FR-R-07 成绩发布（P0）**

教师将评审完成的成绩发布给学生。支持单份发布与批量发布。发布前成绩对学生不可见，发布后状态置"已评审"并触发通知。发布后成绩仍可修改，但修改须留痕并重新通知学生。

**FR-R-08 匿名评审（P1）**

教师可开启匿名（双盲）评审模式，评审时隐藏学生姓名与学号，以编号代替。用于互评或追求评审公平场景。

**FR-R-09 互评管理（P2）**

教师可配置学生互评：每份作业分配给 N 名学生互评，互评学生按量规打分，教师可设置互评成绩权重并复核最终成绩。互评在截止时间后开启，互评学生须先提交本人作业方可参与互评。

#### 3.2.7 申诉与延期（FR-E）

**FR-E-01 延期申请（P1）**

学生在截止时间前或截止后（若不允许补交）提交延期申请，填写申请理由、期望截止时间、佐证附件。申请提交后状态为"待处理"，通知教师。每作业每学生仅可提交一次延期申请。

**FR-E-02 延期审批（P1）**

教师查看延期申请，通过或驳回。通过后该学生该作业的截止时间单独延长至期望时间（或教师修改后的时间），状态标记"已延期"，通知学生。驳回时填写驳回理由，通知学生，维持原截止时间。

**FR-E-03 查重与成绩申诉（P1）**

学生对查重结果或成绩有异议时发起申诉，选择申诉类型（查重异议/成绩异议），填写申诉理由与证据附件。申诉提交后状态为"待处理"，通知教师。申诉须在成绩发布后规定时限内提交（默认 7 天）。

**FR-E-04 申诉处理（P1）**

教师查看申诉详情，可执行以下操作：重新查重（可调整查重参数）、调整成绩、约谈学生（记录约谈结论）。处理完成后填写处理结论（通过改判/驳回维持），通知学生。申诉全过程记录留痕，形成学术诚信档案。

**FR-E-05 申诉状态跟踪（P1）**

学生与教师可查看申诉状态：待处理、处理中、已通过、已驳回。申诉记录永久保留，不随课程归档删除。

#### 3.2.8 通知（FR-N）

**FR-N-01 通知触发（P0）**

系统在以下事件发生时自动触发通知：新作业发布、作业即将截止（提前 24 小时与 1 小时）、查重完成、查重失败、成绩发布、申诉回复、延期申请结果、系统公告。通知内容由模板生成，支持变量插值。

**FR-N-02 通知渠道（P0）**

通知支持多渠道送达：站内信（默认必选）、邮件、短信（可选）、微信/钉钉推送（可选）。每条通知按用户偏好与渠道可用性选择送达渠道。站内信支持已读/未读管理与红点提醒。

**FR-N-03 通知偏好（P1）**

用户在个人中心设置通知偏好，按通知类型开关各渠道。如学生可关闭"即将截止"的邮件通知但保留站内信。

**FR-N-04 通知模板管理（P1）**

管理员维护通知模板，模板含标题与正文，支持变量插值（如 {学生姓名}、{作业标题}、{截止时间}）。模板变更后新通知使用新模板，历史通知不变。

#### 3.2.9 统计分析（FR-ST）

**FR-ST-01 提交进度看板（P0）**

教师查看课程作业的提交进度看板：环形图展示已交/未交/迟交人数，名单表格展示每位学生提交状态与时间。支持一键催交（向未交学生发送通知）。

**FR-ST-02 成绩分布统计（P1）**

教师查看作业成绩分布：直方图、均值、中位数、标准差、及格率、最高分、最低分。支持按班级/小组分组统计。

**FR-ST-03 查重分布统计（P1）**

教师查看作业查重相似度分布图，高风险（超严重阈值）名单单独列出。支持跨届对比（与历届同作业相似度分布对比）。

**FR-ST-04 课程总成绩计算（P1）**

系统按作业权重加权计算课程总成绩。教师可查看每位学生的加权总成绩，可导出成绩单（Excel/CSV）。

**FR-ST-05 异常预警（P1）**

系统自动识别并预警异常情况：相似度超严重阈值、全班零提交、成绩异常集中（如大量相同分数）、单学生多作业低分。预警在教师工作台与管理员看板展示。

**FR-ST-06 系统运营看板（P1）**

管理员查看系统运营数据：用户数、课程数、作业数、查重调用量、系统负载的时间趋势图。支持时间范围筛选。

#### 3.2.10 系统管理（FR-AD）

**FR-AD-01 全局参数配置（P0）**

管理员配置系统全局参数：文件大小上限、允许文件类型、存储策略、查重全局默认阈值、预查重默认配额、申诉时限、迟交扣分规则、是否需要课程审核、压缩包大小上限与解压限制。全局参数作为作业配置的默认值。

**FR-AD-02 系统监控（P0）**

管理员查看系统运行状态：查重队列长度与积压、各服务健康状态、存储用量、接口响应时间、活跃用户数。异常时告警。

**FR-AD-03 日志与审计（P0）**

系统记录以下日志：用户登录日志、业务操作日志（谁在何时对何对象做了何操作）、查重日志、敏感操作日志（成绩修改、申诉处理、用户停用、权限变更）。日志支持按时间/用户/操作类型检索与导出，保留期不少于 1 年。

**FR-AD-04 公告管理（P1）**

管理员发布系统公告与维护通知，公告在全体用户登录后首页展示，可置顶与设有效期。

**FR-AD-05 数据备份与恢复（P1）**

系统支持定期自动备份（每日增量、每周全量）与手动备份。备份内容包括数据库与文件元数据（文件本身由对象存储保障）。管理员可从备份恢复数据，恢复操作须二次确认并记录审计日志。

**FR-AD-06 资源库管理（P0）**

管理员管理查重比对库：历届库入库与剔除、文献库接入配置、白名单维护、互联网比对源开关。入库操作支持批量导入与自动解析。

### 3.7 数据需求

#### 3.7.1 核心数据实体

系统核心数据实体及其关键属性如下。

**用户（User）**：用户ID、学工号、姓名、邮箱、手机、角色、组织ID、账号状态、创建时间。学工号唯一，角色决定权限。

**课程（Course）**：课程ID、课程名称、课程代码、学期、院系、负责人教师ID、简介、状态（待审核/激活/归档）、创建时间。课程代码与学期组合唯一。

**选课记录（Enrollment）**：课程ID、用户ID、角色（学生/助教）、小组ID。表示用户与课程的归属关系。

**作业（Assignment）**：作业ID、课程ID、标题、要求、截止时间、补交配置、多版本配置、查重配置、权重、量规ID、状态、创建时间。作业配置项见 FR-A-01。

**评分量规（Rubric）**：量规ID、作业ID、维度列表（每维度含名称、满分、等级列表）。

**提交（Submission）**：提交ID、作业ID、用户ID/小组ID、版本号、文件URL、在线文本、提交时间、是否迟交、是否生效、状态。同一作业同一用户多版本按版本号递增。

**查重报告（CheckReport）**：报告ID、提交ID、总相似度、分段相似度、来源列表、高亮数据、排除项、算法版本、参数、生成时间。与提交 1:1。

**文件分类记录（FileClassification）**：记录ID、提交ID、文件路径、文件大小、分类桶（A/B/C/D/E/F）、是否参与查重、排除原因。一次压缩包查重对应多条文件分类记录，用于报告中的文件清单展示。

**评审（Review）**：评审ID、提交ID、评审人ID、量规各维度得分、总分、评语、批注、反馈附件、查重结论标记、状态（草稿/已提交）、评审时间。与提交 1:1。

**成绩（Grade）**：成绩ID、提交ID、分数、是否已发布、发布时间、修改记录。与提交 1:1。

**延期申请（ExtensionRequest）**：申请ID、作业ID、用户ID、理由、期望截止时间、附件、状态、处理人ID、处理时间。

**申诉（Appeal）**：申诉ID、提交ID/评审ID、用户ID、类型（查重/成绩）、理由、证据、状态、处理人ID、结论、处理时间。

**通知（Notification）**：通知ID、用户ID、类型、标题、内容、渠道、是否已读、创建时间。

**比对库（CheckLibrary）**：库ID、名称、类型（本班/历届/互联网/文献/白名单）、状态。

**审计日志（AuditLog）**：日志ID、用户ID、操作类型、目标对象、操作详情、IP地址、时间。

#### 3.7.2 数据保留策略

| 数据类型 | 保留策略 |
| --- | --- |
| 提交文件 | 课程归档后保留至毕业后 1 年，之后可迁移冷存储 |
| 查重报告 | 永久保留（学术诚信档案） |
| 文件分类记录 | 随查重报告保留，课程归档后可清理 |
| 评审与成绩 | 永久保留 |
| 申诉记录 | 永久保留 |
| 审计日志 | 不少于 1 年 |
| 通知 | 保留 6 个月后可清理 |
| 比对库内容 | 历届库永久保留，管理员可手动剔除 |

#### 3.7.3 数据一致性要求

-   提交、查重报告、评审、成绩之间保持引用完整性，删除提交须级联处理或阻止。
-   生效版本变更须同步触发查重与评审更新。
-   成绩修改须记录修改前后值与修改人，形成修改链。
-   比对库入库与查重报告生成须最终一致，入库失败不影响报告返回但须告警。
-   文件分类记录与查重报告须保持一致，查重报告生成时同步写入文件分类记录。
