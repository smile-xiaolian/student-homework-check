## 1. 引言

### 1.1 目的

本文档为第一轮迭代开发提供需求基线，明确可运行版本必须实现的功能、性能、安全与数据需求，作为设计、编码、测试与验收的依据。

### 1.2 范围

第一轮迭代交付一个端到端可运行的学生作业提交与查重系统，覆盖从用户登录、课程开设、作业发布、学生提交、文本/代码查重、教师评审打分到成绩发布的完整主流程。系统不依赖 Redis/OpenSearch/RabbitMQ 即可跑通主流程，数据库为唯一业务事实源。

### 1.3 迭代策略与范围总览

系统分两轮迭代开发。第一轮聚焦"可运行的核心闭环"，第二轮补全高级查重（压缩包/混合/预查重/重查）与扩展功能（小组/匿名/互评/申诉/通知增强/统计报表）。

| 功能模块 | 第一轮 [R1] | 第二轮 [R2] |
| --- | --- | --- |
| 用户与权限 | 登录/登出、个人信息、用户管理(含批量导入)、预置四角色 RBAC + 数据范围 | 组织架构、自定义角色、SSO 对接 |
| 课程管理 | 课程创建/编辑/归档、花名册(邀请码+Excel导入) | 助教管理与评审分配、课程公告、教务同步 |
| 作业管理 | 作业发布/编辑/状态流转、查重参数(文本/代码)、量规定义 | 作业附件与白名单材料、混合查重参数、压缩包范围配置 |
| 提交管理 | 提交(文件/在线文本)、多版本与生效版本、状态查询、迟交、文件校验 | 小组提交 |
| 查重引擎 | **文本查重、代码查重**(单/多文件)、报告生成、任务队列、比对库(本班+历届+白名单)、分级预警 | 混合查重、预查重、手动重查、压缩包查重(FR-K-10~15)、互联网/文献库 |
| 评审与反馈 | 评审工作台、在线批注(文本)、量规打分、评语反馈、查重结论标记、批量操作(打分/下载/发布)、成绩发布 | 匿名评审、互评、语音批注、批量重新查重 |
| 通知 | 站内信触发(作业发布/查重完成/查重失败/成绩发布)、站内信渠道 | 截止提醒、邮件渠道、通知偏好、模板管理 |
| 统计分析 | 提交进度看板(简化) | 成绩/查重分布、课程总成绩、异常预警、运营看板 |
| 申诉与延期 | 不实现 | 延期申请/审批、查重与成绩申诉、申诉处理与跟踪 |
| 系统管理 | 全局参数配置、日志与审计、资源库(比对库)管理、简化系统监控 | 公告管理、数据备份恢复、完整监控 |

### 1.4 术语

沿用总体 SRS 术语表。第一轮关键术语：

| 术语 | 说明 |
| --- | --- |
| 文本查重 | 对论文/报告等文本类作业的原创性检测，基于 N-gram/SimHash/MinHash 指纹与 Jaccard/余弦相似度 |

| RBAC | 基于角色的访问控制，叠加数据范围控制 |

## 2. 总体描述

### 2.1 产品视角

第一轮为前后端分离 Web 应用，后端提供 RESTful API，前端浏览器访问。文件存储采用 S3 兼容对象存储（如 MinIO）。查重任务异步执行，第一轮基于数据库任务表（租约 + `FOR UPDATE SKIP LOCKED`）实现队列，不强制引入消息中间件。

### 2.2 功能概览

第一轮功能类别：

| 编号 | 功能类别 | 简述 |
| --- | --- | --- |
| F-01 | 用户与权限 | 账号密码登录、用户管理、预置角色 RBAC |
| F-02 | 课程管理 | 课程创建/归档、花名册维护 |
| F-03 | 作业管理 | 作业发布与查重参数、量规定义 |
| F-04 | 提交管理 | 多版本提交、状态跟踪、迟交处理 |
| F-05 | 查重引擎 | 文本查重、代码查重、报告、比对库 |
| F-06 | 评审与反馈 | 批注、量规打分、成绩发布 |
| F-07 | 通知 | 站内信 |
| F-08 | 系统管理 | 全局参数、审计、资源库 |

### 2.3 用户角色

沿用总体 SRS 四类角色，第一轮均涉及：

- **学生**：提交作业、查看查重报告与成绩反馈。
- **教师**：创建课程/作业、配置查重、评审打分、发布成绩。
- **助教**：第一轮暂不分配评审任务（[R2]），可视为具备课程查看权限的受限教师。
- **系统管理员**：用户管理、全局参数、比对库管理、审计查看。

### 2.4 运行环境

| 项 | 第一轮选型 |
| --- | --- |
| 客户端 | Chrome/Edge/Firefox 主流浏览器，桌面端响应式 |
| 后端 | Java 21 + Spring Boot 3.x（JVM 运行时） |
| 数据库 | PostgreSQL 16+（唯一业务事实库，2 schema：app + audit） |
| 文件存储 | S3 兼容对象存储（MinIO/OSS） |
| 查重队列 | 数据库任务表 + Worker 线程池（租约 + SKIP LOCKED） |
| 缓存 | 可选 Redis；第一轮会话可用 JWT 或数据库 |
| 消息队列 | 不强制；第一轮用进程内事件，[R2] 引入 RabbitMQ |
| 检索 | 第一轮指纹检索用数据库或内嵌实现，[R2] 引入 OpenSearch |

### 2.5 设计与实现约束

- **C-01**：上传文件须经过病毒扫描，禁止可执行文件直接存储与分发。
- **C-02**：查重算法实现须可插拔替换，以支持后续算法升级。
- **C-03**：查重报告须保留算法版本与参数，保证结果可复现。
- **C-04**：系统界面语言为中文。
- **C-05**：所有 SQL 使用参数化查询，防 SQL 注入。
- **C-06**：第一轮不实现压缩包解压查重；代码查重仅支持单文件或多个独立源码文件直传。

### 2.6 假设与依赖

- **A-01**：假设管理员可批量导入用户或手动创建，不依赖教务系统同步（[R2]）。
- **A-02**：假设代码查重所需的语言解析器（Java/Python/C/C++/JavaScript/Go）可集成或实现 AST 解析。
- **A-03**：依赖对象存储服务的高可用性，文件上传后不丢失。
- **A-04**：查重任务队列基于数据库持久化，服务重启后未完成任务可恢复执行。

### 3.2 功能需求

> 编号沿用总体 SRS。每条标注 `[R1]`/`[R2]`。`[R1]` 需求给出完整描述（输入/输出/前置/后置）；`[R2]` 需求仅列编号与归属说明。

#### 3.2.1 用户与权限管理（FR-U）

**FR-U-01 用户登录 `[R1]`**

用户通过账号密码登录（学工号/登录名 + 密码）。系统验证身份与账号状态，成功后建立会话并加载角色权限；失败返回明确错误并记录登录日志。连续登录失败 5 次锁定账号 30 分钟。

- 输入：用户名/学工号、密码
- 输出：成功返回会话令牌与用户信息；失败返回错误码
- 前置条件：账号存在且启用
- 后置条件：成功创建会话并记录登录日志；失败累计失败次数

**FR-U-02 用户登出 `[R1]`**：用户主动登出，系统销毁会话令牌，跳转登录页。

**FR-U-03 用户信息维护 `[R1]`**：用户在个人中心修改姓名、邮箱、手机与密码；修改密码须验证原密码；学工号与角色不可自行修改。

**FR-U-04 用户管理（管理员）`[R1]`**：管理员对用户增删改查，支持按姓名/学工号/角色/状态搜索分页；支持 Excel 批量导入（学工号、姓名、邮箱、角色），导入校验学号唯一性，重复跳过并报告；可启用/停用账号、重置密码；停用立即失效活跃会话。

**FR-U-05 角色与权限管理 `[R1]`**：预置学生、教师、助教、管理员四类角色，每类绑定权限点；权限控制采用 RBAC + 数据范围控制（教师仅本人课程、学生仅本人数据、管理员全局但受审计）。自定义角色与权限矩阵可视化 `[R2]`。

**FR-U-06 组织架构管理 `[R2]`**：院系/专业/班级组织树，第二轮实现。

#### 3.2.2 课程管理（FR-C）

**FR-C-01 课程创建 `[R1]`**

教师创建课程，填写课程名称、课程代码、学期、简介。课程创建后处于"已激活"状态（第一轮不需管理员审核）。课程代码在同一学期内唯一。

- 输入：课程名称、课程代码、学期、简介
- 输出：课程记录，创建者自动成为课程负责人
- 前置条件：用户角色为教师或管理员
- 后置条件：课程创建成功，创建者获得管理权限

**FR-C-02 课程编辑与归档 `[R1]`**：教师编辑本人课程基本信息；学期结束后可归档，归档后课程及作业、提交、成绩只读但可查询；管理员可强制归档。

**FR-C-03 花名册管理 `[R1]`**：教师维护课程学生花名册，支持两种方式：生成邀请码由学生自助加入、Excel 批量导入学号；支持学生退课；花名册变更留痕。教务系统同步 `[R2]`。

**FR-C-04 助教管理与评审任务分配 `[R2]`**：第二轮实现助教指定与评审范围分配。

**FR-C-05 课程公告 `[R2]`**：第二轮实现。

#### 3.2.3 作业管理（FR-A）

**FR-A-01 作业发布 `[R1]`**

教师在课程下发布作业，配置：标题、内容要求、允许文件类型、单文件大小上限、截止时间、是否允许补交及补交截止、是否允许多版本提交及生效版本规则、是否开启查重及查重参数、作业权重、评分量规。发布前可存草稿；发布后学生可见并触发通知。

- 输入：作业配置项
- 输出：作业记录，状态"已发布"
- 前置条件：用户为该课程教师，课程激活
- 后置条件：作业对学生可见，通知花名册学生

> 第一轮不含小组作业、互评配置；作业附件与参考材料 `[R2]`。

**FR-A-02 作业编辑 `[R1]`**：教师编辑已发布作业配置项；截止前编辑不影响已提交内容，截止后编辑须二次确认；查重参数变更后对已生成报告的提交提示影响（第一轮不自动重查，重查 `[R2]`）。

**FR-A-03 作业状态流转 `[R1]`**：状态机简化为 草稿 → 已发布 → 进行中 → 已截止 → 评审中 → 已结束。由系统按时间与操作驱动，教师可手动推进评审阶段。第一轮"已结束"以成绩发布为准（无申诉期）。

**FR-A-04 查重参数配置 `[R1]`**

教师在作业配置中设置查重参数：**查重模式（文本/代码）**、相似度警告阈值、相似度严重阈值、比对库选择、是否排除引用文献、是否排除模板与公共代码。比对库选择规则：**本班库默认开启且不可关闭**；历届库由教师按需启用。第一轮不含混合模式、不含预查重配置、不含压缩包文件范围配置。

**FR-A-05 评分量规定义 `[R1]`**：教师定义评分量规，由多个维度组成，每维度含名称、满分值与等级描述（如优秀/良好/合格/不合格及分值区间）；评审时逐维度打分，系统自动汇总总分。量规模板复用 `[R2]`。

**FR-A-06 作业附件与参考材料 `[R2]`**：第二轮实现。

#### 3.2.4 提交管理（FR-S）

**FR-S-01 作业提交 `[R1]`**

学生在作业详情页提交作业，支持上传文件（一种或多种允许类型）或在线填写文本。系统校验文件类型、大小、截止时间。首次提交须勾选学术诚信声明。提交成功生成新版本号，存储文件并执行预处理；若开启查重，提交后自动投入查重队列。

- 输入：文件或在线文本
- 输出：提交记录（版本号、提交时间、状态）
- 前置条件：学生在花名册内，作业可提交（进行中或允许补交）
- 后置条件：提交记录创建，开启查重则任务入队，进度看板更新

**FR-S-02 多版本提交与生效版本 `[R1]`**：作业允许多版本时，每次提交生成新版本，保留全部历史。生效版本规则：最后一次提交 或 学生手动指定。查重与评审针对生效版本执行。最高分版本规则 `[R2]`（需评审后确定）。

**FR-S-03 提交状态查询 `[R1]`**：学生实时查看每次提交状态（未提交/已提交/查重中/查重完成/查重失败/评审中/已评审），查重中显示排队状态。

**FR-S-04 小组提交 `[R2]`**：第二轮实现。

**FR-S-05 迟交处理 `[R1]`**：超过截止时间提交，若允许补交且在补交截止内，提交成功但标记"迟交"；迟交按配置扣分规则（每日扣 X 分或按比例）在成绩计算时应用；不允许补交则提示已截止。

**FR-S-06 提交文件校验 `[R1]`**：校验文件类型在允许列表内、大小不超上限、病毒扫描通过、文件可正常解析；任一失败拒绝提交并返回原因。

#### 3.2.5 查重引擎（FR-K）

**FR-K-01 文本查重 `[R1]`**

对文本类作业执行原创性检测。默认以本班库为核心比对源进行互同比对，若教师启用历届库则一并纳入。处理流程：文档预处理（PDF/DOCX 转纯文本、编码统一）→ 文本清洗（按配置去除引用标注、模板与公共代码）→ 分句分段 → 特征提取（N-gram 分词生成 SimHash/MinHash 指纹）→ 比对库检索（倒排索引与局部敏感哈希初筛后精排）→ 相似度计算（句子级、段落级、全文级三层粒度，Jaccard 与余弦相似度）→ 报告生成。

- 输入：提交文本内容、查重参数、比对库
- 输出：查重报告（总相似度、分段高亮、来源列表、对比视图、排除项、算法版本与参数）
- 前置条件：提交内容已预处理
- 后置条件：报告持久化，提交状态置"查重完成"，通知学生与教师（高风险提醒）

**FR-K-02 代码查重 `[R1]`**

对代码类作业执行原创性检测。**第一轮支持单文件或多个独立源码文件直传**（学生直接上传 .java/.py/.c 等源码文件），不支持压缩包。处理流程：源码解析 → AST 归一化（去除注释、统一变量名、规范化格式）→ Token 序列提取 → 结构指纹生成（借鉴 MOSS 思路）→ 比对库检索 → 相似度计算（编辑距离与 AST 结构相似度）→ 报告生成。须忽略语法等价但书写风格不同的差异，聚焦逻辑结构相似性。

- 输入：提交的源码文件集合、查重参数、比对库
- 输出：查重报告（总相似度、文件级/函数级匹配、对比视图、算法版本与参数）
- 前置条件：源码文件已通过校验与预处理
- 后置条件：报告持久化，提交状态置"查重完成"，通知学生与教师

> 压缩包代码查重（解压/分类/分层）`[R2]`，见 FR-K-10~15。

**FR-K-03 混合查重 `[R2]`**：第二轮实现。

**FR-K-04 查重报告生成 `[R1]`**

查重完成后生成结构化报告，包含：总相似度百分比（按阈值标红/黄/绿）、分段高亮（原文逐段标注相似段）、来源列表（每条含类型、相似度、出处）、左右双栏对比视图、已排除项清单（引用、模板、公共代码）、查重时间与算法版本与参数（用于复现）。报告以 JSON 存储于对象存储，数据库保存摘要与对象引用；HTML 按需渲染。

> 压缩包文件分类清单 `[R2]`（FR-K-15）。

**FR-K-05 查重任务队列 `[R1]`**

查重为耗时操作，采用异步队列解耦。提交触发查重时任务入队，Worker 消费执行。**第一轮基于数据库任务表实现队列**（租约 + `FOR UPDATE SKIP LOCKED`），支持并发控制与限流。任务失败自动重试最多 3 次，仍失败标记"查重失败"并告警管理员，不影响提交有效性。服务重启后未完成任务可恢复执行。

**FR-K-06 预查重（学生自查）`[R2]`**：第二轮实现。

**FR-K-07 手动重查 `[R2]`**：第二轮实现。第一轮查重失败由自动重试保障；评审阶段以首次报告为准。

**FR-K-08 比对库管理 `[R1]`**

系统维护比对库：**本班库**（本课程本学期已提交作业，查重后自动入库，默认且不可关闭的核心比对源）、**历届库**（历学期归档作业入库，管理员可剔除，教师可选启用）、**白名单库**（教师参考材料，查重时排除，[R2] 随作业附件一并实现；第一轮管理员可手动维护白名单条目）。管理员可管理各库入库、剔除与状态。**互联网库与文献库 `[R2]`**。

**FR-K-09 查重结果分级与预警 `[R1]`**

根据相似度与阈值分级：低于警告阈值为"通过"（绿色），介于警告与严重阈值为"警告"（黄色），超过严重阈值为"严重"（红色）。严重级提交在教师评审工作台置顶预警并通知教师。分级仅作辅助提示，最终判定由教师人工确认。

**FR-K-10~15 压缩包代码查重 `[R2]`**：解压安全校验、文件分类过滤、代码归一化、分层查重比对、文件范围配置、报告文件清单标注，第二轮实现。

### 3.7 数据需求

#### 3.7.1 核心数据实体

第一轮数据实体对齐《数据库设计文档 v1.2》（19 表，2 schema）。第一轮使用的实体：

- **用户**（`app.user_account`）：学工号、姓名、邮箱、手机、系统角色、账号状态。
- **课程**（`app.course`）+ **课程成员**（`app.course_member`）：课程代码+学期唯一；成员课程角色。
- **作业**（`app.assignment`）：查重配置/量规以 JSONB 内嵌。
- **提交**（`app.submission`）+ **提交文件**（`app.submission_file`）：版本号、生效标记、诚信声明、幂等。
- **文件对象**（`app.file_object`）：提交件、报告 JSON、附件共用，含扫描状态。
- **比对库**（`app.check_library`）+ **库条目**（`app.library_entry`）：本班/历届/白名单库，水位序号，owner_hash 排除自比。
- **查重任务**（`app.check_task`）：队列、租约、配置快照、重试。
- **查重报告**（`app.check_report`）：相似度、分级、报告文件引用、摘要。
- **成绩**（`app.grade`）：内嵌评审、维度分、批注、查重结论。
- **通知**（`app.notification`）：站内信。
- **系统配置**（`app.system_config`）：全局参数。
- **审计日志**（`audit.audit_log`）：登录/操作/敏感操作流水，只追加。

第一轮不使用的实体（[R2]）：课程小组、申诉、延期、文件分类（压缩包）、独立量规维度表等。
