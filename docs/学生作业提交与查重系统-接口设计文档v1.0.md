## 1. 文档说明

### 1.1 目的

本文档把需求规格说明书中的功能需求、外部接口需求和业务规则落实为可实现的 API 契约，回答以下问题：

- 前后端之间有哪些接口，分别由哪个业务模块提供；
- 每个接口的路径、方法、权限、输入、输出和错误语义是什么；
- 提交、查重、评审、申诉等异步流程如何通过任务状态与事件协作；
- 文件分片上传、断点续传、预查重配额、报告防篡改等关键能力如何暴露；
- 接口如何满足 RBAC、数据范围、幂等、并发控制、审计和性能要求；
- 需求条目如何追溯到接口，便于开发、测试与验收。

### 1.2 范围

覆盖 SRS V1.2 的十个业务模块：用户与权限、课程、作业、提交、查重、评审与反馈、申诉与延期、通知、统计分析、系统管理。同时覆盖统一身份认证、教务同步、成绩回传、对象存储、消息队列、邮件、短信、文献比对等外部系统接口。

不覆盖：查重算法论文级推导、具体页面视觉稿、数据库完整 DDL、部署脚本。这些内容分别由查重引擎技术方案、UI 设计、数据库设计文档和部署文档承接。

### 1.3 设计原则

| 原则 | 落地方式 |
| --- | --- |
| 资源导向 | URL 表示业务资源，动作通过子资源或受控动作端点表达，不使用动词堆叠的 RPC 风格路径 |
| 契约优先 | 先定义 OpenAPI/JSON Schema，再生成 Mock、客户端与契约测试 |
| 服务端可信 | 截止时间、迟交、成绩、权限、查重结论、配额均由服务端计算，不信任客户端声明 |
| 最小暴露 | 列表不返回大字段；报告正文按需加载；手机号默认脱敏；不返回存储桶路径和内部密钥 |
| 幂等友好 | 提交、预查重、重查、发布成绩等写接口支持 `Idempotency-Key`，重复请求返回原结果 |
| 异步隔离 | 查重、批量操作、病毒扫描、通知投递通过任务或事件异步执行，主业务事务不被长耗时操作阻塞 |
| 不可变留痕 | 查重报告、成绩历史、申诉动作、审计日志只追加；修改通过新版本表达 |
| 三重鉴权 | 全局角色/权限 + 课程成员角色 + 资源状态共同判断，防止 IDOR 与越权 |

### 1.4 术语与缩略语

| 术语 | 说明 |
| --- | --- |
| 资源所有者 | 个人提交为 `USER`，小组提交为 `GROUP`；由 `ownerType + ownerId` 标识 |
| 生效版本 | 当前参与查重、评审与成绩计算的提交版本，同一作业同一所有者唯一 |
| 正式查重 | 由正式提交触发的查重，结果可进入本班库并参与评审 |
| 预查重 | 学生在正式提交前的自查，仅本人可见，不入库、不计入正式报告 |
| 重查 | 教师、申诉或系统补偿触发的再次查重，生成新报告版本 |
| 报告版本 | 同一提交的多次报告按 `reportVersion` 递增，旧版本归档保留 |
| 乐观锁 | 通过 `ETag`/`If-Match` 或 `rowVersion` 检测并发修改 |
| 幂等键 | `Idempotency-Key`，用于在客户端重试时避免重复创建业务对象 |
| 领域事件 | 模块间异步协作消息，采用统一事件信封与版本化类型 |

### 1.5 接口调用方

| 调用方 | 访问方式 | 典型接口 |
| --- | --- | --- |
| Web 前端 | HTTPS + Bearer Token | 全部 `/api/v1/**` 用户接口 |
| 查重 Worker | 内部服务身份 + 任务租约 | 任务领取、阶段回写、报告提交 |
| 通知 Worker | 内部服务身份 + 事件消费 | 通知生成、渠道投递回执 |
| 教务系统 | 服务端到服务端 | 选课同步、成绩回传 |
| 统一认证服务 | OAuth 2.0/OIDC/CAS | 授权码回调、用户信息校验 |
| 对象存储 | S3 兼容接口 | 分片上传、对象读取、生命周期管理 |
| 文献/互联网比对供应商 | 受控外部 API | 查重比对与来源返回 |

## 2. 接口总体设计

### 2.1 逻辑接口架构

```text
Web / Mobile Web
       │ HTTPS + JSON
       ▼
┌─────────────────────────────────────────────┐
│                API Gateway / BFF             │
│  认证、限流、追踪、请求大小限制、路由         │
└──────────────────────┬──────────────────────┘
                       ▼
┌─────────────────────────────────────────────┐
│            模块化单体应用服务                │
│  IAM / Course / Assignment / Submission      │
│  Review / Appeal / Notification / Analytics  │
│  Admin                                       │
└───────┬──────────────┬──────────────┬────────┘
        │              │              │
        ▼              ▼              ▼
   PostgreSQL       Redis         对象存储
        │
        ▼
  持久化事件交换机 edu.events
        │
        ├──────────────▶ 查重编排 / 预处理 Worker
        ├──────────────▶ 比对 Worker / 报告 Worker
        ├──────────────▶ 通知 Worker
        └──────────────▶ 分析聚合任务
```

浏览器只访问业务 API，不直接访问数据库、消息队列或对象存储桶。文件上传使用服务端签发的短期预签名 URL，业务下载默认经 API 鉴权后代理或换取短期下载地址。

### 2.2 接口分区

| 分区 | 路径前缀 | 说明 |
| --- | --- | --- |
| 认证与个人 | `/api/v1/auth`、`/api/v1/me` | 登录、SSO、刷新、登出、个人资料、通知偏好 |
| 用户与权限管理 | `/api/v1/admin` | 用户、角色、组织、全局配置、监控、审计、资源库 |
| 课程 | `/api/v1/courses` | 课程、成员、小组、邀请码、归档、课程公告 |
| 作业 | `/api/v1/assignments` | 作业配置、发布、量规、附件、查重参数 |
| 上传与提交 | `/api/v1/upload-sessions`、`/api/v1/submissions` | 分片上传、提交版本、生效版本、文件访问 |
| 查重 | `/api/v1/check-tasks`、`/api/v1/check-reports` | 任务状态、预查重、报告、文件清单、重查 |
| 评审与成绩 | `/api/v1/reviews`、`/api/v1/grades` | 评审草稿、提交、批注、成绩发布与修改 |
| 申诉与延期 | `/api/v1/extensions`、`/api/v1/appeals` | 申请、审批、处理动作与证据链 |
| 通知 | `/api/v1/notifications` | 站内信、已读、偏好、模板、公告 |
| 统计 | `/api/v1/analytics` | 提交进度、成绩分布、查重分布、课程总成绩、预警 |
| 内部任务 | `/internal/v1/**` | Worker 回写、任务领取、内部健康检查，不经公网暴露 |

### 2.3 协议、域名与版本

- 生产环境基础地址：`https://<domain>/api/v1`。
- 所有业务接口强制 HTTPS，TLS 版本不低于 1.2。
- 请求与响应默认 `application/json; charset=utf-8`；错误响应为 `application/problem+json`。
- 文件下载可使用 `application/octet-stream`、`application/pdf` 或 `text/html`。
- 版本只放在 URL 主版本段；兼容性新增字段不升版本，不兼容修改升级为 `/api/v2`。
- 预发布环境通过请求头 `X-API-Channel: beta` 访问灰度能力，不作为业务逻辑输入。

### 2.4 命名与数据格式

| 项 | 规范 |
| --- | --- |
| JSON 字段 | `camelCase` |
| 数据库字段 | `snake_case`，仅后端内部使用 |
| 路径 | 小写复数名词，单词间用连字符，如 `/check-reports` |
| ID | UUID 字符串，服务端生成；客户端不得自行生成业务主键 |
| 时间 | ISO 8601 UTC，示例 `2026-10-23T02:15:30Z`；前端按 `Asia/Shanghai` 展示 |
| 日期 | `YYYY-MM-DD`，仅用于无时区的统计日期 |
| 金额/分数 | JSON number，最多两位小数；百分比以 `0~100` 表示，不使用 `0~1` |
| 布尔值 | 使用 `true/false`，不使用 `0/1` 或字符串 |
| 空值 | 可选字段缺失或为 `null` 均表示无值；数组字段默认返回 `[]` |
| 枚举 | 大写下划线字符串，如 `CHECKING`、`SUSPECTED_PLAGIARISM` |
| 富文本 | 仅接受经服务端白名单清洗的 HTML 子集；报告 HTML 单独做 CSP 与沙箱处理 |

### 2.5 用户可见状态与内部状态映射

前端使用稳定的业务状态，不直接暴露过多内部任务状态。服务端在响应中同时返回 `status` 与 `statusLabel`，前端以 `status` 为准。

| 用户可见状态 | 内部来源 | 说明 |
| --- | --- | --- |
| `NOT_SUBMITTED` | 无有效提交 | 学生尚未提交 |
| `SUBMITTED` | 提交 `PENDING_SCAN/READY` 且未查重 | 已接收，尚未进入查重或查重未开启 |
| `CHECKING` | 查重任务 `QUEUED/PREPROCESSING/COMPARING/REPORTING` | 显示排队阶段与进度 |
| `CHECK_COMPLETED` | 报告 `isCurrent=true` | 正式报告可用 |
| `CHECK_FAILED` | 查重任务 `FAILED` | 提交仍有效，可重查 |
| `REVIEWING` | 评审 `DRAFT/SUBMITTED` 且成绩未发布 | 教师评审中 |
| `REVIEWED` | 成绩 `published=true` | 学生可见成绩与反馈 |

## 3. 通用接口规范

### 3.1 请求头

| 请求头 | 必需 | 说明 |
| --- | --- | --- |
| `Authorization` | 业务接口必需 | `Bearer <accessToken>` |
| `Content-Type` | 有请求体时必需 | `application/json`、`application/yaml` 或 `multipart/form-data` |
| `Accept` | 否 | 默认 `application/json`；报告 HTML 可请求 `text/html` |
| `Idempotency-Key` | 关键写接口必需 | 16~128 字符，建议 UUID/ULID |
| `If-Match` | 并发写接口必需 | 资源的强 ETag，如 `"row-12"` |
| `X-CSRF-Token` | Cookie 刷新模式下必需 | 与刷新 Cookie 配套，Bearer 请求可省略 |
| `X-Request-Id` | 否 | 客户端请求标识；服务端仍生成独立 `X-Trace-Id` |
| `traceparent` | 否 | W3C Trace Context，网关透传 |
| `Accept-Language` | 否 | 默认 `zh-CN`，用于提示文案，不改变业务错误码 |

### 3.2 成功响应

单资源接口直接返回资源对象，不额外包裹 `code`、`message`：

```json
{
  "id": "019a2f6e-7a3c-7c11-8a5e-2f8f31a9b002",
  "title": "数据库课程设计",
  "status": "DRAFT",
  "createdAt": "2026-10-23T02:15:30Z"
}
```

列表接口统一返回：

```json
{
  "items": [],
  "pagination": {
    "page": 1,
    "size": 20,
    "total": 0,
    "totalPages": 0,
    "hasNext": false
  }
}
```

创建成功返回 `201 Created` 并带 `Location`；异步受理返回 `202 Accepted`；无响应体返回 `204 No Content`。

### 3.3 分页、排序与筛选

| 参数 | 说明 |
| --- | --- |
| `page` | 页码，从 1 开始，默认 1 |
| `size` | 每页数量，默认 20，最大 100 |
| `sort` | 排序字段，前缀 `-` 表示降序，如 `sort=-submittedAt`；字段必须在白名单内 |
| `cursor` | 审计日志、报告来源等大数据列表使用游标，与 `page` 互斥 |
| `status` | 可重复传入，如 `status=QUEUED&status=COMPARING` |
| `q` | 仅用于明确支持的模糊检索，如用户姓名/学工号；服务端限制长度与字段 |
| `from` / `to` | 时间范围，ISO 8601；用于统计与审计 |

筛选参数必须显式定义，禁止客户端传入 SQL、JSONPath、EL 表达式或任意排序表达式。未知参数默认忽略；涉及安全的白名单参数非法时返回 `400 INVALID_ARGUMENT`。

### 3.4 错误模型

错误统一使用 RFC 9457 `application/problem+json`：

```json
{
  "type": "https://errors.example.edu/submission/deadline-passed",
  "title": "提交已截止",
  "status": 409,
  "code": "SUBMISSION_DEADLINE_PASSED",
  "detail": "该作业已截止且未允许补交，请先申请延期。",
  "instance": "/api/v1/assignments/019a.../submissions",
  "traceId": "4bf92f3577b34da6a3ce929d0e0e4736",
  "fieldErrors": []
}
```

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `type` | 是 | 稳定错误类型 URI |
| `title` | 是 | 简短可读标题 |
| `status` | 是 | HTTP 状态码 |
| `code` | 是 | 稳定机器错误码，前端据此分支处理 |
| `detail` | 是 | 脱敏后的可操作说明，不包含堆栈、SQL、服务器路径 |
| `instance` | 是 | 请求路径 |
| `traceId` | 是 | 链路追踪 ID，与响应头 `X-Trace-Id` 一致 |
| `fieldErrors` | 否 | 字段级错误，格式为 `{field, code, message}` |

常用 HTTP 状态：

| HTTP | 使用场景 |
| --- | --- |
| `400` | 参数格式错误、枚举非法、分页参数越界 |
| `401` | 未认证、令牌过期、会话已失效 |
| `403` | 已认证但无权限、课程/数据范围不匹配、归档只读 |
| `404` | 资源不存在，或为防枚举故意不暴露存在性 |
| `409` | 业务冲突，如截止、重复申请、重复生效版本、任务不可取消 |
| `412` | `If-Match` 与当前 ETag 不一致 |
| `413` | 文件或 JSON 超出大小限制 |
| `415` | 不支持的媒体类型 |
| `422` | 语义校验失败，如维度总分不匹配、查重配置非法 |
| `429` | 触发限流，响应带 `Retry-After` |
| `500` | 未预期服务端错误，禁止回显内部细节 |
| `503` | 依赖服务不可用或熔断，响应带 `Retry-After` |

### 3.5 认证与会话

#### 3.5.1 令牌模型

- 访问令牌使用短期 JWT Bearer，默认 15 分钟，包含 `sub`、`roles`、`tokenVersion`、`iat`、`exp`、`jti`。
- 刷新令牌放入 `HttpOnly; Secure; SameSite=Lax` Cookie，路径限定 `/api/v1/auth`，不在 JSON 中返回。
- 访问令牌不携带完整权限清单，服务端按 `tokenVersion` 与 RBAC 缓存实时判定，保证停用或权限变更后快速失效。
- 登出、停用账号、重置密码、权限变更后递增 `tokenVersion`，旧令牌立即失效。
- SSO 用户本地密码为空；本地账号密码仅用于受控应急登录。

#### 3.5.2 权限判定顺序

```text
令牌有效且 tokenVersion 未失效
  → 全局角色/权限点满足
  → 目标资源存在
  → 课程成员角色与数据范围满足
  → 资源状态允许该动作（如未归档、未截止、报告不可变）
  → 执行；失败写审计（敏感动作）
```

任何仅凭 URL 中的 ID 查询资源、不校验归属的实现均视为安全缺陷。

### 3.6 幂等

- 写接口在请求头携带 `Idempotency-Key`，作用域为“用户 + HTTP 方法 + 路径 + 关键资源”。
- 服务端保存键、请求摘要、响应状态与响应体摘要 24 小时；同一键同一请求返回原响应，并带 `Idempotent-Replayed: true`。
- 同一键但请求体不同返回 `409 IDEMPOTENCY_KEY_REUSED`，不得执行新业务。
- 提交接口除通用幂等键外，数据库还以 `(submitterId, assignmentId, idempotencyKey)` 兜底；重复请求返回原提交版本。
- 发布成绩、批量操作、重查、申诉动作等敏感写接口强制要求幂等键。
- 幂等存储不可替代业务唯一约束；两者必须同时存在。

### 3.7 并发控制

评审、成绩、课程、作业、延期和申诉等可修改资源返回强 ETag：

```http
ETag: "row-12"
```

客户端修改时携带：

```http
If-Match: "row-12"
```

版本不一致返回 `412 PRECONDITION_FAILED`，响应 `problem+json` 中带 `currentRowVersion` 与最新资源链接。服务端不得使用“最后写入覆盖”处理评审、成绩、权限等敏感资源。

### 3.8 追踪与审计

- 响应统一返回 `X-Trace-Id`；服务端优先复用合法 `traceparent`，否则生成新追踪 ID。
- 登录、成绩修改、申诉处理、用户停用、权限变更、资源库剔除、全局参数变更写审计日志。
- 审计日志字段与 `audit.audit_log` 对齐：操作人、动作、目标、结果、IP、UA、traceId、变更摘要。
- 审计日志只追加，不提供通过 API 删除的端点。

### 3.9 限流

| 接口类别 | 默认策略 | 超限响应 |
| --- | --- | --- |
| 登录 | 同一 IP + 登录名 10 次/分钟；连续失败 5 次锁定 30 分钟 | `429 LOGIN_RATE_LIMITED` |
| SSO 回调 | 按 IP 与 state 校验，20 次/分钟 | `429 SSO_RATE_LIMITED` |
| 普通查询 | 用户级 120 次/分钟 | `429 RATE_LIMITED` |
| 写接口 | 用户级 30 次/分钟 | `429 RATE_LIMITED` |
| 预查重 | 用户级 3 次/分钟，且受作业配额约束 | `429 PRECHECK_RATE_LIMITED` |
| 重查 | 教师级 10 次/分钟 | `429 RECHECK_RATE_LIMITED` |
| 文件上传初始化 | 用户级 20 次/分钟 | `429 UPLOAD_RATE_LIMITED` |

限流响应带 `Retry-After`，不得因限流扣减预查重配额。

### 3.10 文件上传

#### 3.10.1 上传流程

```text
创建上传会话 → 获取分片预签名 URL → 客户端直传分片
→ 查询缺失分片并可续传 → 完成上传 → 病毒扫描/解析校验
→ 返回 READY 或 REJECTED → 创建提交
```

#### 3.10.2 上传约束

- 默认分片 5MB，可配置；最后一个分片可小于分片大小。
- 预签名 URL 默认 15 分钟有效；上传会话默认 24 小时有效，可恢复续传。
- 单文件上限、允许类型、压缩包大小与解压限制来自系统配置和作业配置的较严值。
- 上传完成后必须通过病毒扫描；扫描未通过的对象位于隔离前缀，不可下载、不可绑定提交。
- 文件类型校验同时使用扩展名、声明 MIME 和文件头/解析结果，不信任客户端 MIME。
- 在线文本提交不创建上传会话，正文上限 1,000,000 字符，入库存摘要。
- 小组提交的文件所有者是小组，但记录实际上传人 `submitterId`。

#### 3.10.3 对象访问

- 业务下载接口先做资源级鉴权，再返回 `302` 短期签名地址或由 API 流式代理。
- 查重报告 HTML、反馈附件、申诉证据等敏感文件的签名地址有效期不超过 5 分钟。
- 禁止将对象存储 key、桶名、内部前缀直接暴露给前端。

### 3.11 缓存与条件请求

- 课程、作业详情等低变更资源可返回 `Cache-Control: private, max-age=30` 与 `ETag`。
- 用户权限、提交状态、查重任务状态不得被浏览器长时间缓存，返回 `Cache-Control: no-store`。
- 客户端使用 `If-None-Match` 获取 `304`，但成绩、申诉、报告正文等敏感资源默认不启用公共缓存。

- 新增枚举值视为兼容变更，但客户端必须对未知值做兜底展示，不得直接崩溃。
- 删除或重命名枚举值视为不兼容变更，必须升 API 主版本。
- `status` 与 `statusLabel` 同时返回；前端展示中文标签，业务分支只使用 `status`。
- 错误码、权限点、事件类型均按命名空间稳定管理，不允许复用已废弃编码。

#### 5.1.3 SSO 登录

```http
GET /api/v1/auth/sso/authorize?redirectUri=https%3A%2F%2Fdomain%2Fauth%2Fcallback&state=<opaque>
```

服务端生成一次性 `state` 与 PKCE 参数并返回 `302` 到统一认证服务。回调：

```http
POST /api/v1/auth/sso/callback
Content-Type: application/json
```

```json
{
  "code": "authorization-code",
  "state": "opaque-state",
  "codeVerifier": "pkce-verifier"
}
```

成功后返回与本地登录相同的令牌结构。首次登录可按配置进行 JIT 创建，用户状态为 `PENDING` 或 `ACTIVE`；账号停用、锁定或组织不合法时拒绝登录。

#### 5.1.4 刷新与登出

- `POST /auth/refresh` 不接收 refresh token 明文，只读取 HttpOnly Cookie；需要 `X-CSRF-Token`。
- 刷新成功后旋转刷新 Cookie；旧刷新令牌立即失效。
- `POST /auth/logout` 销毁当前会话并清理 Cookie，返回 `204`；即使令牌已过期也返回成功。
- 账号被停用或权限变更后，`tokenVersion` 递增，任何旧访问令牌与刷新令牌均不可继续使用。

#### 5.1.5 个人资料与通知偏好

`PATCH /me` 仅允许修改 `displayName`、`email`、`phone`、`avatarFileId`；`userNo`、`roles`、`orgId` 不可由用户修改。

```json
{
  "displayName": "张三",
  "email": "zhangsan@example.edu",
  "phone": "13800000000",
  "avatarFileId": "019a2f6e-7a3c-7c11-8a5e-2f8f31a9b501"
}
```

`PUT /me/notification-preferences` 采用全量更新，避免并发合并歧义：

```json
{
  "preferences": [
    {"notificationType": "DEADLINE_REMINDER", "channel": "IN_APP", "enabled": true},
    {"notificationType": "DEADLINE_REMINDER", "channel": "EMAIL", "enabled": false},
    {"notificationType": "GRADE_PUBLISHED", "channel": "IN_APP", "enabled": true}
  ]
}
```

站内信渠道不可关闭；服务端忽略关闭 `IN_APP` 的请求或返回 `422 IN_APP_CHANNEL_REQUIRED`。

#### 5.5.5 创建提交版本

```http
POST /api/v1/assignments/{id}/submissions
Idempotency-Key: <uuid>
```

```json
{
  "ownerType": "USER",
  "ownerId": "019a2f6e-7a3c-7c11-8a5e-2f8f31a9b203",
  "uploadSessionIds": ["019a2f6e-7a3c-7c11-8a5e-2f8f31a9d001"],
  "onlineText": null,

    "accepted": true,
    "declarationVersion": "2026-09"
  }
}
```

```http
HTTP/1.1 201 Created
Location: /api/v1/submissions/019a2f6e-7a3c-7c11-8a5e-2f8f31a9b201
```

```json
{
  "id": "019a2f6e-7a3c-7c11-8a5e-2f8f31a9b201",
  "versionNo": 2,
  "status": "CHECKING",
  "isEffective": true,
  "isLate": false,
  "submittedAt": "2026-10-23T02:15:30Z",
  "effectiveDeadlineAt": "2026-11-07T15:59:59Z",
  "checkTaskId": "019a2f6e-7a3c-7c11-8a5e-2f8f31a9b204"
}
```

创建提交的核心规则：

- 服务端按“个人延期 > 补交截止 > 正常截止”计算有效截止时间，并冻结到提交记录；客户端时间不参与判断。
- 超过有效截止时间后，若不允许补交返回 `409 SUBMISSION_DEADLINE_PASSED`；若在补交期则 `isLate=true`。
- 首次提交必须提交有效诚信声明；后续版本沿用声明链，但可要求再次确认。
- 文件会话必须属于当前作业、当前所有者，且状态为 `READY`。
- 在线文本与文件至少提供一种；作业策略禁止在线文本时拒绝文本提交。
- 新版本创建后，按生效规则设置唯一生效版本；同一所有者的旧生效版本在同一事务中取消。
- 作业开启查重时，在提交事务提交后创建 `FORMAL` 查重任务；任务创建失败不回滚提交，由补偿任务重试。
- 提交不可物理删除；错误提交通过新版本或作废动作处理，保留审计链。

- `GET /check-reports/{id}/verify` 返回：

报告生成后业务字段不可修改；重查生成新报告版本；任何摘要或签名不匹配均记录安全告警。

#### 5.6.8 重查

单份重查：

```http
POST /api/v1/submissions/{id}/rechecks
Idempotency-Key: <uuid>
```

```json
{
  "reason": "参数调整后复核",
  "configVersionId": "019a2f6e-7a3c-7c11-8a5e-2f8f31a9c001",
  "override": {
    "thresholds": {"textWarning": 15, "textSevere": 40},
    "libraries": ["CLASS", "HISTORICAL"]
  }
}
```

```json
{
  "taskId": "019a2f6e-7a3c-7c11-8a5e-2f8f31a9e101",
  "submissionId": "019a2f6e-7a3c-7c11-8a5e-2f8f31a9b201",
  "reportVersion": 2,
  "status": "QUEUED"
}
```

规则：

- 仅教师/管理员；助教不可重查；
- 重查任务快照当时的配置，不修改历史报告；
- `override` 仅允许阈值、库集合、排除项和归一化开关，不允许关闭本班库或突破安全上限；
- 申诉复核重查使用 `taskType=APPEAL`，并关联申诉追踪号；
- 同提交同一时刻只能存在一个执行中的正式重查任务，重复请求返回已有任务；
- 旧报告在新报告成功生成后自动切换 `isCurrent=false`。

批量重查：

```json
{
  "submissionIds": ["019a...", "019a..."],
  "mode": "FAILED_ONLY",
  "reason": "查重服务恢复后补查"
}
```

`mode` 取 `SELECTED/FAILED_ONLY/ALL`。超过 50 份或 `mode=ALL` 时返回 `202` 与 `batchJobId`，通过批量任务查询接口获取逐份结果。

| 角色 | 可见范围 | 限制 |

| 学生 | 本人正式报告、本人预查重报告 | 不显示其他学生身份；不能查看未完成任务的报告 |

| 助教 | 分配范围内的报告 | 只读；不可重查、不可发布成绩 |
| 管理员 | 全局报告与审计信息 | 访问敏感报告需审计 |
| 归档课程 | 只读查询与导出 | 禁止重查、修改、重新发布 |

报告部分外部库失败时返回 `partial=true` 与 `libraryStatus`，不得把部分失败伪装为完整成功；教师可发起重查。

#### 5.8.5 申诉处理

```http
POST /api/v1/appeals/{id}/actions
If-Match: "row-1"
Idempotency-Key: <uuid>
```

`RECHECK` 示例：

```json
{
  "action": "RECHECK",
  "comment": "按申诉要求调整结构阈值后重新查重",
  "recheck": {
    "override": {
      "thresholds": {"structureWarning": 35, "structureSevere": 65}
    }
  }
}
```

`ADJUST_GRADE` 示例：

```json
{
  "action": "ADJUST_GRADE",
  "comment": "第 2 维度评分偏低，调整后总分为 90",
  "gradeAdjustment": {
    "rawScore": 90,
    "reason": "申诉复核"
  }
}
```

`DECIDE` 示例：

```json
{
  "action": "DECIDE",
  "decision": "APPROVE",
  "conclusion": "申诉成立，已调整成绩并重新通知。"
}
```

动作语义：

| 动作 | 作用 | 状态影响 |
| --- | --- | --- |
| `ACCEPT` | 受理申诉 | `SUBMITTED → IN_REVIEW` |
| `RECHECK` | 发起关联重查任务 | 保持 `IN_REVIEW`，关联 `relatedTaskId` |
| `ADJUST_GRADE` | 调整成绩 | 保持 `IN_REVIEW`，关联 `gradeHistoryId` |
| `INTERVIEW` | 记录约谈结论与证据 | 保持 `IN_REVIEW`，写学术诚信档案 |
| `DECIDE` | 通过或驳回并填写结论 | `IN_REVIEW → APPROVED/REJECTED` |
| `COMMENT` | 添加处理备注 | 不改变状态 |

规则：

- 仅课程教师或管理员；助教不可处理申诉；
- `RECHECK` 未完成时不得直接作最终 `DECIDE`，除非教师明确记录“先结论后补查”并接受审计标记；
- 每个动作追加 `appeal_action`，禁止更新历史动作；
- 重新查重生成新报告、改分写成绩历史、约谈写学术诚信档案，均共享同一 `trackingNo`；
- 结论后通知学生，学生可查看时间线与新报告/成绩；
- 申诉状态未结束时不得物理删除相关提交或证据。

## 6. 异步任务与领域事件

### 6.1 统一事件信封

```json
{
  "eventId": "019a2f6e-7a3c-7c11-8a5e-2f8f31a9b001",
  "eventType": "check.requested.v1",
  "eventVersion": 1,
  "occurredAt": "2026-10-23T02:15:30Z",
  "producer": "teaching-service",
  "aggregateType": "SUBMISSION",
  "aggregateId": "019a2f6e-7a3c-7c11-8a5e-2f8f31a9b002",
  "aggregateVersion": 3,
  "traceId": "4bf92f3577b34da6a3ce929d0e0e4736",
  "payload": {}
}
```

| 字段 | 说明 |
| --- | --- |
| `eventId` | 全局唯一，消费端去重键 |
| `eventType` | `<领域>.<动作>.<版本>`，不兼容变更升版本 |
| `aggregateType` | 聚合类型，如 `SUBMISSION/CHECK_TASK/GRADE/APPEAL` |
| `aggregateId` | 聚合 ID |
| `aggregateVersion` | 聚合版本，消费端忽略过期事件 |
| `traceId` | 链路追踪 ID |
| `payload` | 只包含引用与必要摘要，不包含密码、令牌、完整报告正文、大文件内容 |

### 6.2 消息拓扑

- 持久化交换机：`edu.events`，类型 `topic`。
- 死信交换机：`edu.events.dlx`，绑定 `edu.events.dead`。
- 生产端启用发布确认；消费端手动 ACK。
- 消费失败进入重试队列，按 1s、5s、30s 指数退避，超过最大次数进入死信。
- 消费端按 `eventId` 去重，按 `aggregateVersion` 拒绝过期事件。
- 每个事件类型维护独立队列与消费者并发度，避免慢消费者拖垮全部事件。

```json
  },
  "target": {"type": "CHECK_REPORT", "id": "019a2f6e-7a3c-7c11-8a5e-2f8f31a9b301"},
  "dedupKey": "check-completed:019a2f6e-7a3c-7c11-8a5e-2f8f31a9b301"
}
```

### 6.5 事务性发件箱与一致性

- 业务事务内写业务表和 `platform.outbox_event`，事务提交后由发件箱投递器发布。
- 发件箱记录 `eventId`、聚合版本、负载、状态、重试次数和下次重试时间。
- 事件发布至少一次；消费端必须幂等。
- 查重状态写回、报告切换 `isCurrent`、成绩发布、申诉结论等关键操作使用乐观锁或版本条件。
- 业务侧不得依赖事件即时到达决定同步响应；异步结果通过轮询接口或通知呈现。
- 外部库/外部渠道失败不回滚主业务，采用 `partial`、重试与告警表达。

### 6.6 Worker 内部契约

Worker 通过内部服务身份访问，不暴露公网。实现可采用 AMQP 消费 + 受控内部 HTTP 回调：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/internal/v1/check-tasks/{id}/start` | 领取租约并开始任务 |
| `POST` | `/internal/v1/check-tasks/{id}/heartbeat` | 心跳续租 |
| `POST` | `/internal/v1/check-tasks/{id}/progress` | 回写阶段与进度 |
| `POST` | `/internal/v1/check-tasks/{id}/complete` | 提交报告引用与摘要 |
| `POST` | `/internal/v1/check-tasks/{id}/fail` | 回写错误分类与是否可重试 |

内部接口使用 mTLS 或短期服务令牌，校验 `taskVersion` 与租约；旧 Worker 的过期回传不得覆盖新状态。内部响应不返回给最终用户，但仍需脱敏与审计。

### 7.2 统一认证

- 采用授权码 + PKCE；`state` 一次性、10 分钟有效、服务端校验。
- 认证服务返回 `sub`、姓名、学工号、邮箱、组织等声明；本系统以 `sub` 或学工号做幂等映射。
- JIT 创建用户时默认状态与角色由配置决定；组织不合法或账号停用拒绝登录。
- 认证服务不可用时，仅管理员与授权教师可使用受控本地账号应急登录；普通学生仍走 SSO。
- 登出同时注销本地会话，并按认证服务能力发起单点登出。

### 7.4 成绩回传

系统提供两种模式：

- 文件导出：Excel/CSV，字段映射模板可配置，适用于教务系统无实时接口的场景。
- 接口推送：`POST <教务系统成绩接口>`，使用 mTLS/OAuth 客户端凭据，按课程代码+学期+学号幂等。

内部触发接口：

```http
POST /api/v1/courses/{id}/grades/return
Idempotency-Key: <uuid>
```

```json
{
  "term": "2026-FALL",
  "format": "JSON",
  "onlyPublished": true,
  "dryRun": false
}
```

返回 `202` 与 `returnJobId`。每条回传记录保存外部业务号、回执状态、失败原因和重试次数；成绩修改后需重新回传并保留新旧回执。

### 7.5 对象存储

- 使用 S3 兼容 API，分片上传、预签名 URL 与生命周期策略。
- 对象前缀按 `course/<courseId>/assignment/<assignmentId>/submission/<submissionId>/` 隔离。
- 上传对象先进入隔离前缀，扫描通过后转为可读对象；扫描失败对象由生命周期清理。
- 预签名 URL 默认 15 分钟；下载 URL 不超过 5 分钟。
- 服务端保存对象元数据与摘要，不保存永久公开 URL。
- 删除采用生命周期和受控清理，不直接物理删除审计所需文件。

### 7.6 消息、邮件、短信与推送

- AMQP 使用持久化消息、发布确认、手动 ACK、死信队列与消费幂等。
- 邮件通过 SMTP/HTTP 网关，记录投递回执与脱敏错误码；失败不回滚业务。
- 短信默认关闭，启用时校验用户偏好、配额与敏感词；日志只记录脱敏号码。
- 微信/钉钉推送作为可选适配器，通过统一 `NotificationChannel` 接口接入。
- 外部渠道失败只影响对应渠道，站内信始终落库。

### 7.7 文献/互联网比对供应商

概念请求：

```json
{
  "requestId": "019a2f6e-7a3c-7c11-8a5e-2f8f31ab001",
  "contentType": "TEXT",
  "contentRef": "s3://internal-precheck/...",
  "language": "zh-CN",
  "options": {
    "includeInternet": true,
    "includeLiterature": true,
    "maxResults": 50
  }
}
```

概念响应包含 `sources[]`、每条来源相似度、标题、可展示片段和供应商请求号。规则：

- 必须校验教师显式启用与授权配置；
- 超时 10 秒，失败最多重试 1 次，连续失败触发熔断；
- 外部库失败时本班库结果仍可生成，报告标记 `partial=true`；
- 供应商密钥通过 KMS/Vault 引用，不进入业务数据库明文；
- 返回来源只展示供应商允许的内容，不缓存超出授权期限的全文。

### 7.8 病毒扫描与可选扫描仪

- 上传完成后发送 `file.scan.requested.v1`，扫描服务返回 `CLEAN/INFECTED/ERROR`。
- 扫描超时 60 秒，失败不放行；扫描服务不可用时提交接口返回 `503 FILE_SCAN_UNAVAILABLE`。
- 扫描结果写审计，不记录文件内容。
- 扫描仪上传通过浏览器 TWAIN/WIA 采集为 PDF/图片，再走普通上传会话与病毒扫描，不建立独立信任通道。

### 8.2 资源级授权

每个资源接口必须校验：

1. 当前用户是否已认证且账号有效；
2. 全局角色/权限点是否允许该动作；
3. 资源是否存在且未归档/未删除；
4. 课程成员角色是否匹配（学生、助教、教师）；
5. 数据范围是否匹配（本人、本人课程、分配评审范围）；
6. 业务状态是否允许该动作（截止、查重完成、成绩已发布等）；
7. 敏感动作是否携带二次确认与审计原因。

禁止只按 URL 中用户 ID、课程 ID、提交 ID 查询后直接返回；资源查询 SQL 必须带课程/所有者范围条件。对无权限资源统一返回 `403`，对可能枚举的 ID 返回 `404`。

### 8.3 输入与文件安全

- 所有输入做长度、类型、枚举、范围和字符集校验；SQL 使用参数化查询。
- 富文本使用服务端白名单清洗，禁止事件属性、脚本、外链 iframe 和 `javascript:`。
- 文件类型同时校验扩展名、MIME、文件头与解析结果；压缩包在沙箱解压，限制大小、文件数、嵌套深度与超时。
- 拒绝路径穿越 `../`、绝对路径、符号链接和超长路径。
- 预签名 URL 绑定对象键、方法、过期时间，不授予列表权限。
- 报告 HTML 使用 `sandbox` 与严格 CSP，在线查看时禁止自动执行脚本。
- 外部 URL 抓取/文献比对执行 SSRF 防护，禁止访问内网、元数据地址和非授权协议。

### 8.4 隐私与数据最小化

- 手机号、邮箱在列表默认脱敏；只有本人、管理员或确有必要且被授权的教师可见完整值。
- 学生互评与双盲评审隐藏姓名、学工号；日志与报告来源使用匿名标识。
- 日志禁止记录密码、令牌、完整身份证件、完整手机号、文件内容和查重正文。
- 报告来源对学生隐藏其他学生身份，教师视图按课程授权展示。
- 申诉档案永久保留；课程归档不删除申诉、成绩历史、审计与报告摘要。
- 数据导出生成受控下载链接并记录导出审计。

### 8.5 性能目标与接口超时

| 接口类别 | 目标 | 服务端超时/限制 |
| --- | --- | --- |
| 查询类 | P95 ≤ 500ms | 服务端处理 3s，超时返回 503 |
| 写入类 | P95 ≤ 1s（不含文件上传/异步查重） | 5s |
| 文件上传初始化 | P95 ≤ 500ms | 3s |
| 分片上传 | 50MB ≤ 30s | 单分片 5MB，预签名 15 分钟 |
| 文本查重 | 10 万字 ≤ 60s P95 | Worker 120s 软超时 |
| 代码查重 | 5000 行 ≤ 90s P95 | Worker 180s 软超时 |
| 压缩包解压 | 100MB ≤ 30s P95 | 60s 超时 |
| 压缩包代码查重 | 100 个源码文件 ≤ 180s P95 | Worker 可按全局配置放宽 |
| 报告页 | 首屏 ≤ 3s P95 | 摘要优先，分段/来源按需加载 |
| 查重并发 | 20 路并行 | 超出排队，优先级正式提交高于预查重 |

网关请求体限制：普通 JSON ≤ 2MB；Excel 导入 ≤ 10MB；单文件按全局配置；报告分页每页 ≤ 100 条。超限返回 `413`。

### 8.6 幂等与并发复核

| 场景 | 幂等/并发机制 |
| --- | --- |
| 创建提交 | `Idempotency-Key` + `(submitter, assignment, key)` 唯一约束 |
| 创建上传会话 | `uploadSession.idempotency_key` + 文件摘要 |
| 预查重 | 幂等键 + 配额原子预占 |
| 正式重查 | 幂等键 + 同一提交执行中任务唯一 |
| 生效版本切换 | 行锁/范围锁 + 部分唯一索引 |

| 成绩发布/改分 | 幂等键 + 成绩行版本 + 历史追加 |

| 用户停用/权限变更 | 行版本 + `tokenVersion` 递增 |

### 8.7 可观测性

必须输出的指标：

- API：请求量、P50/P95/P99、错误率、4xx/5xx、限流次数、活跃用户数。
- 提交：请求量、成功/失败、迟交数、重复幂等命中、文件扫描失败数。
- 查重：队列长度、排队时长、各阶段耗时、成功率、重试数、死信数、外部库失败率。
- 评审：待评审数、草稿/已提交数、成绩发布数、改分次数。
- 业务异常：报告签名校验失败、越权尝试、归档后写尝试、事务回滚率。

必须输出的日志字段：`traceId`、`requestId`、`userId`（脱敏或内部 ID）、`action`、`targetType`、`targetId`、`result`、`durationMs`、错误码。日志分级与采样不得遗漏审计事件。

### 8.8 降级与失败策略

| 依赖故障 | 降级策略 |
| --- | --- |
| 查重 Worker 不可用 | 提交仍成功，任务排队；界面显示查重中；恢复后继续 |
| 外部文献/互联网库失败 | 本班库结果照常生成，报告 `partial=true` |
| 通知渠道失败 | 站内信保留，外部渠道重试并记录失败 |
| 教务系统不可用 | 使用现有花名册；同步任务延后重试 |
| 对象存储不可用 | 上传/下载返回 503；不创建半成品提交 |
| 病毒扫描不可用 | 不放行文件，提交被拒绝并提示稍后重试 |
| 数据库主库不可用 | 写接口返回 503；只读副本继续提供只读页面（若配置） |

### 8.9 审计要求

必须审计的动作：登录成功/失败、登出、用户创建/修改/停用/解锁/重置密码、角色权限变更、课程归档、作业发布与配置修改、查重参数修改、手动重查、成绩发布/修改、申诉动作、延期审批、资源库入库/剔除、全局参数修改、审计导出、备份恢复。

审计记录不包含密码、令牌、完整报告正文和未脱敏个人数据。审计查询与导出本身也记录操作人和查询条件。

## 9. 版本兼容与契约治理

### 9.1 OpenAPI 作为唯一契约

- 仓库维护 `openapi/openapi-v1.yaml`，OpenAPI 3.1 为接口事实来源。
- 每个端点定义 `operationId`、请求体 Schema、响应 Schema、错误响应、安全方案和示例。
- 从 OpenAPI 生成 TypeScript 客户端、Mock Server 与契约测试；前端不手写接口类型。
- 事件负载维护独立 JSON Schema，纳入 CI 兼容性检查。
- 数据库字段不直接暴露为 API；通过 DTO 与字段映射控制。

### 9.2 兼容性规则

| 变更 | 兼容性 | 处理 |
| --- | --- | --- |
| 新增可选请求字段 | 兼容 | 不升版本 |
| 新增响应字段 | 兼容 | 客户端忽略未知字段 |
| 新增枚举值 | 兼容 | 客户端必须兜底未知值 |
| 修改字段含义/类型 | 不兼容 | 升 `/api/v2` 或新字段并行 |
| 删除字段/接口 | 不兼容 | 先弃用并至少保留一个版本周期 |
| 修改默认分页/排序 | 不兼容 | 显式版本化或迁移公告 |
| 事件新增可选字段 | 兼容 | 不升 eventVersion |
| 事件删除/改语义 | 不兼容 | 发新版本事件并行 |

### 9.3 弃用流程

1. OpenAPI 标记 `deprecated: true`，响应头返回 `Deprecation` 与 `Sunset`。
2. 至少保留一个发布周期或 90 天，取较长者。
3. 提供迁移说明与新端点映射。
4. 监控旧端点调用量，确认无关键调用方后下线。

### 9.4 契约测试

- 后端：OpenAPI 请求/响应校验、权限矩阵测试、错误码快照测试。
- 前端：基于生成的客户端进行编译期检查与 Mock 契约测试。
- Worker：事件 JSON Schema 验证、幂等消费测试、乱序与重复投递测试。
- CI 阻断：不兼容 Schema 变更未升版本、错误码未登记、示例与 Schema 不一致。

## 10. 需求追溯

### 10.1 功能需求到接口

## 11. 接口验收检查单

| 检查项 | 验收标准 |
| --- | --- |
| 路径与方法 | 所有端点符合 `/api/v1` 与资源命名规范，OpenAPI 中存在对应定义 |
| 认证 | 除登录、SSO、健康检查外均要求有效 Bearer Token |
| 授权 | 每个资源接口验证全局权限、课程角色、数据范围与资源状态 |
| 请求校验 | 字段类型、长度、枚举、业务约束均有服务端校验 |
| 响应契约 | 单资源、列表、分页结构统一；时间、百分比、枚举格式一致 |
| 错误 | 使用 `problem+json`，错误码稳定，不泄露堆栈/SQL/路径 |
| 幂等 | 提交、预查重、重查、发布、审批、批量操作支持幂等键 |
| 并发 | 评审、成绩、配置、审批使用 ETag/If-Match 或行版本 |
| 文件 | 分片上传、续传、扫描、大小/类型校验、鉴权下载完整 |
| 异步 | 查重、批量、导出、通知均有任务或事件状态可查 |
| 报告 | 报告只读、版本化、签名可校验、按需分页加载 |
| 权限边界 | 教师不能跨课程、学生不能跨人、助教不能越范围 |
| 归档 | 归档后写操作被拒绝，查询与导出仍可用 |
| 安全 | 敏感字段脱敏，日志无令牌/密码，外部密钥不落库 |
| 性能 | 查询/写入 SLO、分页上限、限流、超时与降级策略明确 |
| 审计 | 敏感操作记录操作人、对象、结果、IP、traceId |
| 兼容 | 新增字段兼容、删除字段有弃用周期、事件版本可并行 |
| 测试 | 每个 P0 端点有契约测试、权限测试、错误路径测试 |

### 12.3 接口设计决策记录

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 成功响应是否加统一 `code` | 不加 | 使用 HTTP 状态与资源体，错误才使用 problem+json |
| 百分比范围 | 0~100 | 与 UI 展示和 SRS 阈值一致，避免 0~1 混用 |
| 文件上传方式 | 预签名分片直传 | 降低 API 带宽压力，支持断点续传与进度 |
| 查重响应方式 | 202 + 任务轮询/通知 | 查重耗时，不能阻塞提交 |
| 查重报告正文 | 摘要 + 按需分页 | 控制响应大小和首屏性能 |
| 报告修改 | 禁止修改，重查新版本 | 满足防篡改与可复现要求 |
| 配置版本 | 发布后不可改，新建版本 | 历史查重可复现 |
| 学生身份在报告来源中 | 默认匿名 | 保护隐私、降低互评冲突 |
| YAML 查重配置 | 仅交互格式，落库 JSONB | 统一 Schema 校验与执行语义 |
| 成绩修改 | 追加历史，不允许覆盖 | 审计与申诉可追溯 |
| 外部渠道失败 | 不阻断业务 | 站内信必达，外部渠道可重试 |
| 归档数据 | 只读保留 | 满足课程档案与申诉长期留存 |
